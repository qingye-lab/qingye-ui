本次没有联网查询 npm，发布是否成功以发版记录为准。

### 4. Studio 风险：事实成立，定级取决于前提

已核实的事实：

- `apps/studio/server/service.mjs:35-55` 只接受 localhost 的 Host；`GET /api/session` 向同源页面返回 nonce 和项目路径；POST 请求校验同源 Origin，并用 `timingSafeEqual` 比对 nonce。
- `apps/studio/src/main.tsx:40` 的「应用主题」按钮直接调用 `model.apply(session.nonce)`，没有二次确认。

裁决：这是给**本地单人工具**设计的跨站请求防护，同源页面本来就需要拿到 nonce。在现有用法下，它不是缺陷。"高危"只在一个前提下成立：**有浏览器 Agent 被接到一个挂着真实项目的 Studio 上**。本机工具链（内置浏览器、Playwright 脚本）确实能做到这一点，所以把它记为前提条件：在允许 Agent 驱动 Studio 写入真实项目之前，必须先给 Agent 单独的会话凭据，或者在写入前要求人工确认。现在不改代码。

### 5. 示例页的"改完立即保存"不是真实写入

`apps/docs/src/examples/workspace/settings.tsx:90` 的角色 Select 在 `onValueChange` 里直接修改内存状态。这是没有后端的示例页，不存在真实的持久写入，不需要修改。

### 6. S1-T4 的 `RouterLink` 是消费端的路由链接

`RouterLink` 不是本库的组件。官网在 `apps/docs/src/components/locale-link.tsx` 里把 react-router-dom 的 `Link` 起名为 `RouterLink`。S1-T4 的题面必须写明"消费项目使用 react-router"，否则期望答案（路由链接配合 `buttonVariants`）不成立。题目草案里的其他 API 都已核实存在：`buttonVariants`、`DataTablePattern`、`SearchInput`、`Composer`、`TableContainer framed`、`ConfirmAction`；`TooltipTrigger` 的 `render` 是必填项。

### 7. 消费端误用已在 2026-10-23 处置

S0 列出的误用都已处理或写进文档，见 `docs/decisions/2026-10-23-consumer-migration-feedback.md`，包括 Drawer `swipeDirection`、Progress `value={null}`、Select 的 `""` 与 `null`、Alert role、`TableContainer framed={false}`、Field 上下文。用它们出题，检验的是"Agent 有没有读到文档"，不是在找新缺陷。
