# 布局与导航族判据

## Status

Proposed（2026-10-03）。七族判据第七份（最后一族）。依据 [design.md](../../design.md)、[基础层](2026-10-03-foundation.md)、[组件分层](component-layering.md)。

## 一、这一族处理什么真实问题

一个人要**在多个工作面之间移动，并知道自己在哪、能去哪、怎么回来**。

不是「放几个链接」，是：在窄屏收起导航后仍能到达、在深层页面知道上级在哪、在内容之间建立可读的关系而不靠围合。

**核心问题**：如何让**位置**与**到达**两件事在任意屏幕与任意深度下都成立。

## 二、参与的与不参与的方法

| 方法 | 参与 | 在这一族的后果 |
|---|---|---|
| 展开有据 | **主导** | 层级可深入，**且每层都有返回**；当前位置始终可知 |
| 随境取度 | **主导** | 窄屏改承载（侧栏→抽屉），**导航能力与层级不变** |
| 布白有用 | **参与** | 用间距与对齐建立关系，不靠围合；内容开放而操作有界 |
| 相成相制 | **参与** | 导航与主工作面共处；布局容器不改内容的语义 |
| 名实相符 | **参与** | 导航是到达，命令是动作；二者不得互换 |
| 进退相承 | 参与（有限） | 收起/展开是本地状态；**当前位置归应用** |

## 三、由关系强制出的八个决定

### 决定 1：**当前位置**由应用持有，组件只呈现

「我在哪一页」是路由事实。

**禁止**：组件从 URL 自行推断高亮项并声称知道当前位置。组件接受当前位置，不计算它。

### 决定 2：**导航是到达，不是命令**

导航（`Breadcrumb` / `NavigationMenu` / `Pagination` / `Tabs` / `Steps` / `Sidebar` 的链接）产生位置变化；命令（`Menu`）产生动作。

**推出**：二者的可访问语义不同（`link` / `aria-current` vs `menuitem`），不得互换。用按钮做导航会让「这个会把我带到别处」不可预期。

### 决定 3：**每层深入都有返回**

展开有据：层级可深入，返回必须存在。

| 组件 | 返回方式 |
|---|---|
| `Breadcrumb` | 明确的上级路径 |
| `Sidebar` 折叠 | 折叠状态本身可逆 |
| `Tabs` | 当前项始终可见 |
| `Steps` | 已完成步可回到 |
| `Tree` | 折叠即返回 |

**禁止**：`Breadcrumb` 依赖浏览器历史（design.md 原文：返回依赖不存在的历史）。

### 决定 4：**窄屏改承载，不改能力**

随境取度：

| 桌面 | 窄屏 | 必须保持 |
|---|---|---|
| 常驻侧栏 | 抽屉或收起 | 全部入口可达 |
| 横向 tabs | 可滚动 tabs | 当前项可见 |
| 多列导航 | 单列 | 层级不变 |

**禁止**：窄屏删掉某个层级或某一组入口。

### 决定 5：**关系用间距与对齐建立，不靠围合**

布白有用 + NG4。

**推出**：布局容器（`Layout` / `Group` / `Toolbar`）提供**关系角色**（间隔、对齐、分节），不提供「给这里加个框」的便利。

### 决定 6：**布局容器不改变内容的语义**

`Layout` / `Group` 只决定位置与间隔。它们不改内容的可访问语义、不改状态归属、不发请求。

**禁止**：把布局容器当作状态容器或数据容器。

### 决定 7：**方向与密度由容器传递**

基础层 §13/§14：密度、方向、语言由容器传递，单位自己不声明。

**推出**：本族的容器是**这些角色的传递者**，必须保证传递到子树。

### 决定 8：**动效所有权**（基础层 §12）

抽屉式导航的入场退出归 `motion.css`。本族组件不声明第二套。

## 四、本族的单元构成

本族是七族中成员最多的（22 个），按**它决定什么**分组：

| 分组 | 成员 | 决定什么 |
|---|---|---|
| **基础布局** | `Layout`、`Group`、`Toolbar`、`AspectRatio`、`Separator` | 位置、间隔、比例、分节 |
| **排版** | `Typography`、`CodeBlock` | 文字与代码的语义角色 |
| **应用外壳** | `Sidebar`、`PageHeader` | 长期导航与页首 |
| **层级导航** | `Breadcrumb`、`Pagination`、`Steps` | 位置与进度 |
| **内容切换** | `Tabs`、`Accordion`、`Collapsible` | 同一对象上的视角切换 / 展开 |
| **内容承载** | `Carousel`、`ScrollArea`、`VirtualList` | 序列与长内容的可达 |
| **文件** | `FileUpload` | 文件的选择、上传、失败与重试 |

**边界说明**：

- `disclosure` 已删（与 `collapsible` 同义）
- `frame`、`preview-card` 已删（无独立身份 / 产品特定）
- `resizable` 已删（布局能力，且与「不动画 width」冲突）
- `StatusDot` 归展示族，不在本族

## 五、逐组件定位与关键取舍

| 组件 | 定位 | 关键取舍 |
|---|---|---|
| `Layout` | 页面级位置与间隔 | 不提供围合；不改内容语义 |
| `Group` | 相邻单位的共同关系 | 只给间隔与对齐 |
| `Toolbar` | 常驻操作组 | 承载操作，**不声明范围**（那是 `bulk-action-bar`） |
| `AspectRatio` | 按比例占位 | 无状态、无交互 |
| `Separator` | 分节 | 是关系标记，非装饰 |
| `Typography` | 语义文字角色 | 档位来自基础层 §8；中文不套负字距 |
| `CodeBlock` | 代码呈现 | 含复制动作的组合 |
| `Sidebar` | 长期导航与主工作面 | 收起是本地状态；当前位置归应用 |
| `PageHeader` | 页首 | 不放维护者向信息；不重复面包屑 |
| `Breadcrumb` | 上级路径 | **不得依赖浏览器历史** |
| `Pagination` | 集合的分页到达 | 当前页归应用 |
| `Steps` | 流程位置 | 当前步归应用；已完成步可回 |
| `Tabs` | 同一对象的视角切换 | 切换**不产生新对象**；当前项归应用或本地受控 |
| `Accordion` | 同层级内容的展开 | 展开是本地状态 |
| `Collapsible` | 单块内容的展开 | 与 `Accordion` 的差别是是否成组 |
| `Carousel` | 序列的横向浏览 | 键盘可达；不自动播放 |
| `ScrollArea` | 长内容滚动 | 可滚动性可见 |
| `VirtualList` | 超长集合 | 虚拟化不破坏键盘与焦点 |
| `FileUpload` | 文件选择与上传 | 失败保留已选；**不发请求**（应用负责） |

## 六、这一族最容易做错的六件事

| # | 错误 | 违反 | 判据 |
|---|---|---|---|
| 1 | `Breadcrumb` 依赖浏览器历史 | 展开有据 | 直接打开深层链接后上级是否可用 |
| 2 | 窄屏删掉一组导航入口 | 随境取度 | 窄屏能否到达全部入口 |
| 3 | 用按钮做导航 | 名实相符 | 键盘与读屏是否得到链接语义 |
| 4 | 布局容器围合内容 | 布白有用 / NG4 | 去掉边框后关系是否改变 |
| 5 | `Tabs` 切换时重建对象 | 相成相制 | 切换后输入与焦点是否保留 |
| 6 | 组件自行推断当前项 | 名实相符 | 同一路径在多处使用时高亮是否正确 |

## 七、与基础层的关系

消费 §3（间距角色：关系间隔）、§4（圆角：面板身份）、§6（表面层级：侧栏与浮层）、§8（文字档）、§12（动效所有权：**抽屉归 `motion.css`**）、§13（密度与三轴：**由容器传递**）、§14（方向与语言：**本族的 RTL 风险最高**）、§15（焦点：Tabs / Accordion / Menu 的键盘）、§18（组合契约：**本族是「局部让位于整体」的主要落点**）。

**本族不新建数值。**

## Alternatives

**未把 `resizable` 保留。** 分栏拖拽是布局能力而非组件，且依赖 `width` 动画，与「不动画 width」相抵触。

**未把 `frame` 保留。** 与 `card` 的独立边界职责重叠；NG4 的删去检验不通过。

**未让布局容器提供围合。** 那会诱导无差别套卡，且让「内容是否需要独立边界」这个判断被便利取代。

**未让 `Tabs` 自行推断当前项。** 当前位置是路由事实，属于应用。

**未保留 `disclosure`。** 与 `collapsible` 同义，保留两个名字违反名实相符。

## Consequences

- 22 个组件中 `sidebar`（763 行）、`carousel`（462 行）、`file-upload`（576 行）最大，重写风险最高。
- `typography` 的档位依赖基础层 §8 的收敛结果，必须在 F1 完成后才能重写。
- `breadcrumb` / `pagination` / `steps` 都需要「当前位置由应用给」的契约变更，属破坏性变更。
- 本族的 RTL 与容器查询（`@container`）验证成本最高，需要在试点中确认验证方式。
- 七族判据至此全部产出。若在试点中发现形式不适用（例如某族需要不同的结构），回改本文与其余六族并说明。

## 八、补：Provider 类（跨族基础）

三个 Provider 不属于任一业务族，它们提供**运行时契约**，归 Foundation 层（见分层文档）。

| 组件 | 提供什么 | 归本族的原因 |
|---|---|---|
| `ThemeProvider` | 明暗轴的运行时写入与无闪烁脚本 | 它写文档级属性，是全局位置而非组件行为 |
| `MotionProvider` | 输入方式与减少动态效果的运行时契约 | 同上 |
| `LocaleSwitch` | 在运行时切换语言 | 它改变的是全局语言上下文，与方向/语言同属 §14 |

**三者的共同点**：它们改的是**环境**，不是某个对象。因此归 Foundation，在本文中作为「跨族基础」列出，不参与业务族的逐组件判据。

| 决定 | 内容 |
|---|---|
| 只写自己那一轴 | 基础层 §13：品牌 `data-brand`、明暗 `light`/`dark`、密度 `data-density` 不混用 |
| 不改变权限与保存策略 | 主题只改视觉 |
| 切换语言后焦点与输入保留 | 基础层 §14：文字长度不得导致结构错乱 |
| SSR 无闪烁 | 已在 `theme-provider.tsx` 的脚本中实现，重写时保留该能力 |
