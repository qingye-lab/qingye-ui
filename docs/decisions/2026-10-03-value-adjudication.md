# 逐值裁决：审查发现与处置

## Status

Decided（2026-10-03）。依据根 `design.md`；输入为三份**独立审查**报告
（`/tmp/qy-review/{1-foundation,2-primitives,3-consistency}.md`），
审查者对同一份材料独立判断，互不可见。

## 一、这次审查暴露的根本问题

三份报告独立收敛到同一条：

> **作者把「我选的」写成了「理念要求的」。**

具体分为四类，本文件对每一处给出处置：

| 类别 | 含义 | 处置 |
|---|---|---|
| **推导** | 理念的某条唯一决定了该值，换值即违反 | 保留，并给出反证 |
| **约束** | 理念给出区间或单调性，区间内取值是选择 | 保留，**改写文档**：明说是选择并给出区间 |
| **追认** | 作者写了理由，但该理由不强制此值 | 保留值（若无更好依据），**删掉伪造的理由** |
| **继承** | 值来自旧实现，改名不改变来源 | 逐项复核，能推导的补推导，否则记为预设 |

**关键区分：追认不等于数值不可用。** 问题是文档声称它是必然的。
处置是**改文档**，不是改值——除非该值同时违反了一条真实关系。

## 二、已执行的修复（有实测证据）

### 修复 1：焦点信号全部收进控件自身边界

**用户原话**：「我说的是无框」「输入框说的是外围那个高亮的那个效果」。

| 部位 | 修复前 | 修复后 | 证据 |
|---|---|---|---|
| Input 主体 | 外环（已在此前修掉） | 边框变色 + 1px 内描边 | `boxShadow: inset 0 0 0 1px`，盒 x=134，信号在盒内 |
| **Input 清空/密码按钮** | **外扩 1px，越出输入框外边界** | `focus-visible:ring-inset` | 见下 |
| **quiet 按钮** | **2px 外环** | `focus-visible:ring-inset` | `--tw-ring-inset: inset` |
| solid / danger 按钮 | 已是 inset | 不变 | 同上 |

**R3 对 Input 附属按钮的像素证据**（修复前）：

```text
light 900 input-clear:
actionRight=867; hostRight=868; ringRight=869; outsideWidth=1
[-1, 0.875]  rgba(38,38,38,255)   ← 在 host 外边界之外
[1, 4]       rgba(246,246,246,255)
```

**核实**：R2 与 R3 各自独立测出同一缺陷。这条是本次最实质的发现——
用户明确要求的「控件外面不出现任何一圈」，在普通文本 Input 上已经满足，
但在**它的附属按钮上仍然违反**。

### 修复 2：裸 PopoverTrigger 的命中层覆盖视口（High，功能缺陷）

**R2 实测**（修复前）：390×844 视口下，触发者自身 `302×24`，
但其 `::after` 为 **390×844**，`elementFromPoint(195,422)` 命中它 ——
**点击屏幕中央会打开浮层**。

**根因**：`utilities.css` 的 `touch-target` 注释写着「宿主必须已定位」，
但这是一个**在 19 个消费文件中无人强制**的前置条件。宿主是 static 时，
`position: absolute` 的伪元素相对视口解析，`max(100%, 44px)` 里的 `100%`
于是变成视口宽度。

**修复**：让工具类**自己建立定位上下文**，而不是要求 19 个调用方各自记得写 `relative`。
这是「能组合解决的不增加配置」用在工具类上。

**核实**（修复后）：伪元素 `88×44`，`viewportCentreHitsTrigger: false`。

### 修复 3：强制颜色模式下焦点完全消失（High）

**R2 实测**：`forced-colors: active` 下，solid/quiet Button、Card 链接、
Popover 入口聚焦后 `box-shadow: none`、`outline: none`、`border-width: 0`
—— **前后逐像素完全相同，焦点不可见**。

**根因**：本库把焦点信号**全部**放在 `box-shadow` 这一个通道上，
而强制颜色模式会移除它。信号存在一个会被系统剥夺的通道里。

**修复**：在 `styles.css` 基础层为 `@media (forced-colors: active)`
恢复 `outline`。因为组件的 `outline-none` 位于 utilities 层，层序胜过
选择器特异性，此处必须用 `!important` —— 这是**唯一**为满足可访问底线
而越过常规层序的地方，已在注释中说明。

**核实**（强制颜色模式）：

```text
normal : solid=box-shadow  quiet=box-shadow  card-link=box-shadow
forced : solid=outline 2px quiet=outline 2px card-link=outline 2px
```

## 三、需要改写文档的条目（值保留，理由重写）

以下各处**值不改**，但文档必须停止声称它们是唯一解。
每条的「真实定位」栏是要写进基础层的表述。

| # | 文档原写法 | 审查结论 | 真实定位 |
|---|---|---|---|
| 1 | 「尺寸绝不表达重要性」 | 理念无此禁令；尺寸与功能角色应解耦，但有理由的较大保护入口合法 | **约束**：两个轴独立可选；尺寸参与表达需有任务理由 |
| 2 | 「所有嵌套元素必须圆角同心」 | 12px 面板 + 24px 内边距含独立 8px 按钮时，`r内=r外−inset` 为负 | **约束**：仅对**同一条承载轮廓等距内缩**成立；独立子对象不适用 |
| 3 | 「可编辑区和所有浮层一律加边界」 | 理念要求可辨认，不要求必须描边 | **约束**：必要识别机制必须；描边只是可选机制之一 |
| 4 | 「危险动作必须每次同时出现说明或保护」 | 理念反对重复警告；已说清的后果无需再加包装 | **约束**：后果必须在场；由**就近可见的表达**承担，不必然是专用包装 |
| 5 | 「水平留白 ≤ 外高 50%」为唯一硬约束 | 32px 高配 18px 留白也成立 | **选择**：40–44% 是预设；容量上限由真实宽度与内容决定 |
| 6 | 「反馈只能加强已有属性／offset 必须为零」 | 理念无此两句 | **推导（后半）**：信号不得是控件**外围**新增的一圈（用户明确要求）／**选择（前半）**：内描边宽度 |
| 7 | 「事实由应用持有」推成「禁止 boolean loading」 | 传 `loading=true` 完全满足理念 | **选择**：联合状态 API 是可用的接口设计，不是理念强制 |
| 8 | 字距随字号递减、触摸字号必增、单行必截断 | 理念未规定这些绝对值 | **预设**：可作为默认，不得冒充底线 |

**第 7 条已进入实现**：`Button` 在 `tone="danger"` 且无 `ButtonProtection` 时**直接抛错**。
这挡住了「后果已在别处清楚说明」的合法组合。这是**过度规则进入实现**的证据，
需要放宽为「后果必须在场且可关联」，而非「必须包在指定容器里」。

## 四、继承值的复核（R3 逐字比对结果）

R3 用 AST 提取字符串字面量，与冻结基线逐字比较。**改名不等于独立推导**：

| 值 | 处置 |
|---|---|
| `--qy-focus-ring-width: 2px` | **2px 是选择**。WCAG 2.4.13 的 2px 是 **AAA** 的面积下限，不是 AA 要求；AA（2.4.7）只要求可见，1.4.11 要求 ≥3:1。文档须如此表述 |
| `disabled:opacity-64` | 逐字继承。**保留为预设**，理由需重写或标注来源 |
| `bg-primary/90` 悬停/按下 | 逐字继承。预设 |
| `z-50` | 逐字继承。预设 |
| 入场 `scale(.98)` / `opacity(0)` | 逐字继承（迁入 `motion.css`）。预设 |
| `--qy-control-*` 尺寸序列 | 逐字继承。**保留**（外部尺寸可由预设选择确定），文档停止声称由理念推出 |
| `.98` / `64%` / `90%` 等 | 一律标为**预设**，不写「推导」 |

**同时应当记录**：R3 确认 `ring-offset` 与 `ring-ring/24` **已从四份源码中删除**，
不是「换名保留」。区分继承与已删除，不能用旧值指控当前实现。

## 五、审查页自身的缺陷（R3 发现）

我建的三个审查页**存在证据污染**，不能作为库现状的证据：

| 页面 | 问题 |
|---|---|
| `/review/focus` | 用 `!important` 强加旧的外环样式，并把已改好的 inset 按钮**重新渲染成旧 offset 外环**；且声称「每列都在键盘聚焦态」，实测初始只有**一个**元素有焦点 |
| `/review/boundary` | 把候选边框加在**内部 input** 上，真实外层边框与焦点线仍在——改错了边界所有者 |

**处置**：这两个页面保留但**标注为「候选对比，非库现状」**，
或在下一轮重做。`/review/pilot` 与 `/review/focus-fallback` 无此问题。

## Consequences

- 基础层 §1、§2、§4、§5、§10、§15、§18 需按第三节改写表述（值多数不动）。
