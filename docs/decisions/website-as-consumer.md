# 官网作为组件库的第一方消费端

当前裁决：2026-10-03 重写任务，执行收尾跨至 2026-10-04；2026-10-30 随 5.0.0 补充新组件的采用（见文内同日一节）。取代本文件早期的 88 模块、业务任务模拟和移动外壳安排；历史裁决见对应日期的计划与执行记录。

## 任务与边界

官网帮助人识别组件、打开真实示例、查当前 API，并把同源设计指南带入项目。当前目标为已重写的 83 个组件，目录数量与示例来自 `content/*/meta.ts` 和当前 registry，不另维护计数或示例库存。

- 首页是介绍项目作用的落地页，不是目录（用户 2026-10-08）。同日经多轮否决（目录、左右对撑、居中窄栏、硬拉宽、放大的图谱、标注画布），用户最终放开约束：「可以左右布局……我不限制你了……你设计需要使用我的项目理念」，并以 Linear 为精致度标尺。
- 2026-10-08 深度评审后，用户要求重新设计首页，改善设计与交互。现行结构为：产品名与技术定位；总纲及真实设计摘录组合（搜索、选择、密度、复制）；实际按钮尺寸与 DOM 几何；五级中性墨阶；安装 / AI 接入。交互控件复用库，摘录只属于当前示例，不模拟业务请求。详细表面与状态契约见 `apps/docs/.impeccable/surfaces/apps-docs-src-pages-home-tsx.md`。
- `/docs/components/:slug` 与 `/components/:slug` 共用组件内容身份；playground 裸页消费同一 registry 和 demo ID。预览、源码、API 与键盘信息保留各自用途。
- `/examples` 是一个完整的多页工作区示例（概览、集合、集合详情、设置、帮助），只用本库公开组件组合，随 `src/examples/` 路由。用户 2026-10 裁决：`/examples` 不受“不模拟业务场景”约束，必须是真实页面；数据是本地假数据，没有真实请求或服务。未知路径、未知工作区页面与未知设置分组都进入站点统一的 not-found 状态；跳转保留 URL 语言前缀。
- `/docs/patterns` 是当前 Pattern 公共结构目录。已删除业务模式的详情路由进入 not-found，不从归档恢复旧消费者。`generate-fixtures.mjs` 保持构建调用入口但不再生成无人消费的假业务资源。
- 所有交互控件复用本库公开组合；页面结构、表单分组和原生链接保留 HTML 语义。链接外观可用 `buttonVariants`。NativeSelect 的原生 option/optgroup 是其必要结构，并非一套另造的基础控件。
- 当前范围是桌面网站，Header 直接呈现导航；不为旧 Sheet 恢复移动菜单，`/examples` 的侧栏也不启用窄屏抽屉（`Sidebar drawer`）。Disclosure、Frame 不是当前库的组件，不恢复（折叠用 Collapsible）。Skeleton 与 Command 是当前库的公共组件，官网按任务使用：Skeleton 用于路由首次加载与预览加载的轮廓，Command 用于搜索面板（见「语义与状态」）。

## 语义与状态

站点搜索由库的 `Command` 放进 `Dialog` 组成（`components/search-dialog.tsx`）。不用 `CommandDialog`，因为选择结果后要把页面标题/主区域交给 `DialogPopup` 的 `finalFocus`，`CommandDialog` 不暴露它。结果来自当前指南与组件，匹配与排序仍由 `lib/search.ts` 的 `score` 决定：`Command` 的过滤恒为真，条目按得分次序渲染，无匹配时 `CommandEmpty` 说明「没有匹配的内容」，不发明结果。`Command` 在列表变化时自动高亮首位，所以输入后直接 Enter 打开最佳匹配，方向键再向下移动。选择结果后焦点由原语实际聚焦到页面标题，避免在关闭回调中提前 focus 造成重入；取消归还原触发位置。

`/examples/workspace` 的外壳是库的 `Workspace`：侧栏、`WorkspaceSurface`、`WorkspaceHeader` 与 `WorkspaceContent` 组成，外壳自带跳过链接与侧栏、工作面之间的间隔。侧栏导航的名称写在 `SidebarContent` 上（`Sidebar` 根不再是地标）；页面级操作经 `WorkspaceHeaderPortal` 进入顶栏，位于顶栏的搜索与动态之后。内容区保持 `id="main"`，站点的跳过链接与路由后的焦点仍落在它上面。工作区内的搜索是 `CommandDialog`（集合名称包含匹配）；应用内 ⌘K 在捕获阶段接下并止步，不与站点文档搜索同时打开。

草稿和已应用条件分别保存；应用后才改变结果，取消回到已应用条件。Tabs 保留隐藏面板的草稿。复制成功由 Clipboard Promise 确认，拒绝后呈现公共 CopyButton 错误反馈。加载和渲染失败按对应局部说明，重试不丢弃文档邻接内容；未知、空与不适用分别使用当前 Empty 状态。

侧栏选中项在当前原生 ScrollArea 容器内滚动到可见处，使用真实 `data-slot="scroll-area"`，不依赖已删除的 Viewport 部件。

## 首页与示例重做（2026-10-30）

用户：「重新帮我设计官网……太丑了……唯一的约束就是，采用我的项目理念以及项目组件」，随后补充「主要是首页……其次是示例」。本裁决取代下文「信息架构」中首页一段与 2026-10-12「首页只有三件事、不摆组件样张」的约束；文档框架、页头与侧栏不在本次范围。

**首页第二稿**（同日，用户：「首页太丑陋了，AI 味道很浓」，要求以 frontend-design、emil-design-engineering、taste-skill 与 Impeccable 的 audit / polish 组合重做）。前两者实际加载；taste-skill 与 Impeccable 不在可用目录里，按其公开的原则人工执行，不冒称运行。四者与 design.md 冲突时以 design.md 为准：不用「以阴影代替边框」，不加入场与滚动动效（NG6）。

第一稿的审查结论：左文右台的分栏首屏是最通用的 SaaS 首屏；四章同一个骨架（左题右网格）、十五个等权方块、六个色块、三个入口方块——重复的等权单元正是生成式页面的痕迹，也违反 NG2。第二稿每段的形式随内容换（`pages/home.tsx`、`home-window.tsx`、`home.css`、`lib/home-methods.ts`、`lib/axes.ts`）：
- 首屏：总纲一行（display-xl），全页唯一的大字；定位与两个动作紧随其下，与总纲同一条左缘。
- 产品窗口：示例应用本身，全宽、可操作。窗口顶栏是唯一的控件区：起始侧换示例（工作区 / 采集记录 / 会议室预约），结束侧是主题三轴；三轴经同源 postMessage 写进框内文档的根（`lib/axes.ts` 的 `applyAxes`），整个应用一起换、不重载；换示例才换地址。窄于 48rem 时先打开预约（工作区与记录是桌面范围的应用）。裸框路由取消滚动条空槽。
- 总纲：三段宣言式正文（title 档），名为焦墨、释义为浓墨，出处是页边注；名、出处与含义逐字取自 design.md 总纲表。
- 十五法：design.md 原本就是两张表，首页仍用库的 `Table` 呈现名、设计决定、出处三列；表容器向两侧伸出一个面板内缘，使首列文字与全页文字同一条左缘（实测全页文字左缘只有一条，x = 53）。
- 开始使用：一行，标题、安装命令与四个去处。
- 删去：组件查找台、色块、入口方块、`ComponentStage`。
- 预设：首屏上留 5 材、首屏到窗口 2 × 章内间隔、章间 3 × 章内间隔、窗口框高 36 材、总纲正文 36 材 / 注 14 材 / 栏距 4 材、表的名列 10 材与出处列 18 材。

**本站品牌：青**（`index.css` 的 `html[data-brand="qingye"]`）。取自「青野」；只覆写 `--qy-primary` 与前景，实心按钮、选中标记与站标的点随之换色，其余仍是墨阶（墨分五色：品牌强调色如一方印）。浅色 oklch(0.48 0.085 200)，白字其上 6.2:1；深色 oklch(0.78 0.09 195)，深前景其上 9.1:1。色相与明度是预设，对比按 sRGB 换算核对，未经 contrast-check 工具实测。局部嵌套的 `.light/.dark` 根会重置为墨（库的语义块在每个明暗根上重算 `--qy-primary`）；首页窗口的品牌写在框内文档的根上。

**示例**（`examples/gallery.tsx`、`list.ts`、`booking.tsx`、`examples.css`）。
- `/examples` 从直接跳转工作区改为总览：每个示例一行，与首页同一张两栏网格，起始栏是类型、名称、说明、用到的组件（链接到组件页）与打开 / 源码，内容栏是它的真实缩略——裸框路由 `/frame/examples/:id` 在 iframe 里按 1/2 缩放，懒加载、`inert`、不进读屏。
- 查看页：框上方一行是「示例 › 名称」与查看源码；未知示例 id 仍是站点统一的未找到状态。
- 原有「采集记录」（`content/workspace/demos/03-records`）此前没有入口，现在列入总览。
- 新增「会议室预约」（日常应用，与工作区的专业工具形成对照）：左侧 Steps 同时是已填内容的摘要；人数受房间容量制约，错误落在人数上并给出两条出路；与已有预约冲突的房间不可选，原因写在它自己的说明里；提交失败后焦点落到第一个无效字段；返回保留草稿；确认后可以撤销，撤销回到核对这一步、草稿仍在。数据只在本页，「已预约」的 Alert 写明刷新后清除，不模拟请求。

验证（第二稿）：docs `tsc`、`check:components`（0 违例）、`pnpm --filter docs test`（61/61）；Playwright 实测窗口三轴写进框内根（class、data-density、--qy-primary 计算值）且换示例后保留，预约流程的校验、焦点、容量冲突、返回保留与撤销，1440 / 1024 / 390 宽无横向溢出、无控制台错误。未做：读屏实测、真实中文输入法、contrast-check 工具对品牌色的实测、`scripts/audit.mjs` 全量扫描。

## 5.0.0 新能力的采用与不采用（2026-10-30）

只在新组件确实对应原任务时采用，不为「用上」硬塞。已采用：Command（站点搜索、工作区搜索）、Workspace 系列（示例外壳）、`useCopyToClipboard`（Tooltip 评审页的复制，http 下可回退）。组件页自身的 demo 与 meta 已随库提交带有 Command、Resizable、ColorPicker、TimeField、FileTrigger、Cascader、TreeSelect 的文档。

未采用及理由：

| 能力 | 理由 |
| --- | --- |
| Resizable | 官网与示例没有手写的可调宽布局；集合详情用抽屉预览，是浮层动作，不是常驻的列表与详情并置，换成分栏会改变任务。 |
| ColorPicker | 主题试验台选的是有名字的品牌预设（附浅深两套色与对比验证），不是一个自由取得的 #rrggbb 用户数据。 |
| TimeField、FileTrigger、Cascader、TreeSelect | 站点与示例里没有对应的任务；设置页的默认权限是勾选的 Tree，不是选择值。示例里没有现成的时间或文件设置，不为展示新增。 |
| DataTable 吸顶表头、固定列、busy、error | 集合表格分页、八行、不横向溢出，没有有界高度容器；数据是本地假数据，没有请求，不虚构「取数中」或「失败」。行名称（`meta.rowHeader`）与「选择范围」（`scope="filtered"`）已在使用。 |

## 信息架构（2026-10-08）

用户反复指出：各页导航不一样且位置会变；文档页版式不统一；首页、示例与其他页的页头和宽度在切换时会变；理念、法度若放进文档，页头就不需要它们。取舍结果：

**一个壳。** 所有页面（首页、文档、组件、示例）同一个页头：吸顶、一条底线、页面背景色、同一宽度。宽度是 `--site-width` = 66 材（侧栏 12 + 间隔 2 + 正文 40 + 间隔 2 + 目录 10，正好是文档框架的总宽），两侧最小留白 2 材，`.site-frame` 居中；`html` 设 `scrollbar-gutter: stable`，有无滚动条的页面宽度相同。页头、首页、文档框架、示例画布都用 `.site-frame`，不再各写版心与内边距。

**一棵导航树。** 页头只有文档、组件、示例三个入口（库的 `NavigationMenu`），当前页点亮它所属的一处（`navScope`）。理念与法度在文档里，不进页头。侧栏是库的 `Sidebar`（`components/docs-nav.tsx`），在每个文档页内容与位置都相同；`DocsLayout` 只有一个路由父级，切页不重挂载。顺序即阅读顺序，上一页/下一页沿同一顺序：

| 组 | 页面 | 排序理由 |
|---|---|---|
| 开始 | 介绍 → 安装 → AI 使用 | 第一次接入 |
| 理念与法度 | 设计理念 → 基础判断 → 设计令牌 | 为什么，怎样判断，每个值从哪来 |
| 指南 | 主题 → 动效 → 国际化 → 无障碍 | 在项目里落地，改动由大到小 |
| 组件 | 总览 → 组件组合 → 十个分类（折叠） | 参考；当前页所在分类展开，其余按读者的折叠保持 |

动效在指南：它是怎样配置 MotionProvider 的说明，台账的「动」一节另有取值。

**一种字体。** 全站只用库的 `--qy-font-sans`（系统黑体：苹方 / 微软雅黑 / 思源黑体）与系统等宽；层级靠字号、字重与墨色，由库的字阶（display / title / chapter / heading）给出。曾用系统宋体做页题与章节标题、网页字体 Geist Mono 做代码，2026-10-08 撤销，理由：（一）用户 2026-10-07 已裁决「全项目一套系统字体」，并撤回过宋体正文；（二）design.md「材有美」：默认系统字体，外加拉丁字面使同一行出现两套 x 高度，正是被列为不应做的事；（三）理念正文与 design.md 都写明不取仿古字体——宋体与「取其法，不取其形」相悖；（四）宋体是印刷字，只在 macOS 有可靠的屏幕字面（苹方才是），Windows 回退到中易宋体，小字号锯齿明显，同一页在不同平台是两种样子，违背合宜为度；（五）不下载任何字体文件。若要品牌字体，走品牌层覆写 `--qy-font-sans`，不在页面里另指定。

**一套文章版式，所有页相同。** 页题 display 档、章节 title 档、小节 chapter 档，正文 reading 档、行长 34 字、中文两端对齐并严格避头尾；段间一材，小节两材，章节三材。这些写在 `prose.tsx` 与 `index.css`，页面不覆盖。理念页的出处改为正文上标链接加文末「来源简注」，边注与 `EssayFrame` 已撤销。
