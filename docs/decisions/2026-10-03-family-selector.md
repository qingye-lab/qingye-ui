# 选择器族判据

## Status

Proposed（2026-10-03）。七族判据第五份。依据 [design.md](../../design.md)、[基础层](2026-10-03-foundation.md)、[组件分层](component-layering.md)。

## 一、这一族处理什么真实问题

一个人要**从一组候选中给出一个值**，而这组候选**可能很多、可能远程、可能允许自己填**。

不是「选一个」，是：在不知道有多少选项时找到那个值、在选项不在列表里时如实表达、在选中之后保留已选的事实。

**核心问题**：如何让「候选范围」与「当前值」这两件事**同时可读**，并且在远程与未知长度的情况下仍然成立。

## 二、参与的与不参与的方法

| 方法 | 参与 | 在这一族的后果 |
|---|---|---|
| 名实相符 | **主导** | 值是值，候选是候选；「未选」与「选了空值」不同；远程未返回 != 没有选项 |
| 随境取度 | **主导** | 候选很少与候选很多是不同的承载；窄屏与桌面可换承载，**语义不变** |
| 进退相承 | **参与** | 远程加载、失败、未知围绕**同一个值**；失败不清空已选 |
| 相成相制 | **参与** | 值、候选、过滤条件、已选范围互相约束 |
| 展开有据 | **参与** | 候选展开有理由；已选可回看 |
| 布白有用 | 不参与 | 候选列表的空间由承载决定 |

## 三、由关系强制出的七个决定

### 决定 1：**「未选择」**、**「选择了空值」**、**「候选为空」**、**「候选未返回」**是四种事实

| 事实 | 表达 |
|---|---|
| 用户尚未选择 | 占位提示（但不作为唯一名称） |
| 用户明确选择了空值 | 显示空值 |
| 候选确实为空 | 「没有可选项」 |
| **候选尚未返回** | 加载状态或「未知」 |

**禁止**：把「候选尚未返回」显示为「没有可选项」。这会让用户以为范围已穷尽。

### 决定 2：**值**与**候选**是两个不同的状态，归属不同

| 状态 | 归属 |
|---|---|
| 当前值 | 应用 |
| 候选列表 | 应用（尤其远程） |
| 打开/关闭、高亮项 | 组件 |
| 过滤输入 | 组件（受控时归应用） |

**禁止**：组件因候选加载失败而清空已选值。

### 决定 3：承载由**候选规模**决定，不由「长得好不好看」决定

随境取度：

| 候选规模 | 承载 |
|---|---|
| 少（可一次看完） | 内联列表或短浮层 |
| 多 | 带过滤的浮层 |
| 远程/未知长度 | 同上 + 加载与失败状态 |
| 窄屏 | 可换整屏面板，**语义不变** |

**禁止**：因为窄屏而删掉过滤能力。

### 决定 4：**可控输入**与**受控选择**是两个不同语义

| 语义 | 组件 | 用户能做 |
|---|---|---|
| 只能从候选选 | `Select`、`NativeSelect` | 选择 |
| 可以输入也可以选 | `Combobox`、`Autocomplete` | 输入 + 选择 |
| 只能输入 | `Input` | 输入 |

**推出**：`Combobox` 与 `Autocomplete` 的差别不是「自动补全」，而是**候选的来源与触发方式**（本地过滤 vs 远程查询）。二者应当在文档中说清判据，否则会被任意选用。

### 决定 5：**原生语义**在需要时必须保留

`NativeSelect` 存在是因为平台原生选择器在移动端、表单提交、自动填充上有不可替代的行为。

**推出**：它不是 `Select` 的降级版本，是**另一个语义**。二者不能互相替代。

### 决定 6：**分段输入**有独立状态机

`OtpField` 与 `TagInput` 不是 `Input` 的形态：

- `OtpField`：分段、粘贴分配、自动推进、回退
- `TagInput`：集合而非单值；标签是**已确认项**，未确认的输入是草稿

**推出**：二者保留为独立组件（见分层文档）。

### 决定 7：**数值**是带约束的值，不是文本

`NumberField` 表达「一个有范围与步进的数」。因此：

- 范围与步进是**约束**，不是格式化
- 越界是**事实**，由应用定义如何处理
- 不做「猜测的进度」或自动纠正

## 四、本族与表单族的关系

本族的组件是**表单族 `Field` 的可替换控件**（表单族决定 1 的验证点）：换控件不改变字段的名称、说明、错误行为。

因此本族**不实现自己的标签、说明、错误**——那些属于 `Field`。

## 五、逐组件定位与关键取舍

| 组件 | 定位 | 关键取舍 |
|---|---|---|
| `Select` | 从候选选单值 | 候选由应用给；不因加载失败清空已选 |
| `NativeSelect` | 平台原生选择语义 | 独立语义，非降级版 |
| `Combobox` | 本地候选 + 可输入 | 过滤是组件行为，候选取值归应用 |
| `Autocomplete` | 远程候选 + 可输入 | 加载/失败/空三种状态必须分别表达 |
| `NumberField` | 带范围与步进的数值 | 越界是事实；不自动纠正 |
| `OtpField` | 分段固定长度 | 独立状态机；粘贴分配必须有定义 |
| `TagInput` | 集合输入 | 标签是已确认项；未确认输入是草稿 |
| `Input` | 单值文本（吸收 search / password 形态） | 搜索与密码是**形态**，不是独立组件 |

## 六、这一族最容易做错的六件事

| # | 错误 | 违反 | 判据 |
|---|---|---|---|
| 1 | 远程未返回显示为「没有可选项」 | 名实相符 | 未返回时用户是否以为范围已穷尽 |
| 2 | 候选加载失败清空已选值 | 进退相承 | 失败后已选是否保留 |
| 3 | 窄屏删掉过滤 | 随境取度 | 窄屏能否完成同样的选择任务 |
| 4 | 用 `Select` 替代 `NativeSelect` | 名实相符 | 移动端是否仍可用原生选择器 |
| 5 | 未确认的标签输入被当作已选 | 名实相符 | 输入一半的内容是否出现在值里 |
| 6 | 越界数值被静默纠正 | 进退相承 | 用户输入 999 显示 100 是否被明确告知 |

## 七、与基础层的关系

消费 §1/§2（控件几何）、§5（边界：可编辑区必须有边界）、§6（表面：候选浮层）、§8（文字档）、§9（状态归属，**决定 1 与 2 的落点**）、§12（动效所有权：候选浮层归 `motion.css`）、§15（焦点：候选列表的键盘导航）、§17（内容容量：**决定 1 的落点**）、§18（组合契约：与 `Field` 的组合）。

**本族不新建数值。**

## Alternatives

**未把 `search-input` / `password-input` 保留为组件。** 它们的语义仍是「输入文本」；搜索行为属于 Pattern（`filter-bar`），可见性切换是 input 的附属动作。

**未把 `Autocomplete` 与 `Combobox` 合并。** 候选来源不同（远程查询 vs 本地过滤），失败与加载状态的处理不同。合并会让「远程候选」的加载状态无处表达。

**未把 `NativeSelect` 视为降级。** 它在移动端有不可替代的原生行为。

**未让本族实现标签与错误。** 那属于 `Field`，本族只是可替换控件（表单族决定 1）。

## Consequences

- `input` 需要新增搜索与密码两种形态；`search-input`、`password-input` 的页、示例、`meta.ts` 删除。
- `autocomplete` 与 `combobox` 的文档需要写清判据，否则会被任意选用。
- `tag-input`（499 行）与 `combobox`（441 行）较大，重写时需按本文逐项核对。
- 本族与表单族的组合关系需要在 `Field` 的文档中给出示例（换控件不改变字段事实）。

## 八、补：`SegmentedControl`

`SegmentedControl` 是**在少量候选中切换当前项**，视觉上是一组并列的段。

它归本族而非 Tabs：**Tabs 切换的是同一对象的视角（不产生新值），SegmentedControl 产生一个新值。**

| 决定 | 内容 |
|---|---|
| 它是值的输入，不是视角切换 | 值是应用的事实，可由组件受控 |
| 轨道与选中项的表面关系 | 基础层 §6：`surface-inset` 承载，选中项 `surface-raised` |
| 取消选中后轨道仍成立 | 基础层 §6 |
| 候选很少时才适用 | 候选多时应用 `Select`（随境取度） |
| 键盘 | 方向键在段之间移动，与 Tabs 类似但产生值变化 |
