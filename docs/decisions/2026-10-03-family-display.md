# 展示族判据

## Status

Decided for Card（2026-10-03，按逐值裁决修订）；其余重写目标为 Proposed。依据 [design.md](../../design.md)、[基础层](2026-10-03-foundation.md) 的 18 项、[组件分层](component-layering.md)。当前本族只有 Card 与 Separator 文件；其余表列成员是族目标，不表示已导出。

## 一、这一族处理什么真实问题

一个人要**读一批内容，并且在其中做出判断**。

不是「把数据显示出来」，是：比较几项、看出主次、知道当前有哪几项、知道有没有、知道正在读的是哪一项。

**核心问题**：如何让一批内容**同时在场**，并且让读者能判断出「重点在哪、我在哪、还有什么」。

与动作族的分工：内容承载与动作入口分别承担职责。Card 可通过 render 成为链接等入口，内部也可组合动作；这不让 Card 自行掌握业务请求或结果。

## 二、参与的与不参与的方法

| 方法 | 参与 | 在这一族的后果 |
|---|---|---|
| 布白有用 | **主导** | 关系间隔、比较空间、判断余地分别安排；紧凑不等于缩小文字 |
| 名实相符 | **参与** | 空、零、未知、不适用分别表达；数字与文字各自说自己的事实 |
| 相成相制 | **参与** | 内容与承载共处；围合必须由独立身份决定，不是为了好看 |
| 展开有据 | **参与** | 概要到深入有理由，且有返回 |
| 随境取度 | 参与（承载） | 窄屏改承载方式（并置→逐条），**不删必要比较列** |
| 进退相承 | 参与（有限） | 刷新时保留仍有效的工作面；不因加载清空旧内容 |

**注意**：展示族**不参与**的部分是「动作」。展示族里的按钮（如表格行操作）属于动作族，不因此让展示族承担动作语义。

## 三、由关系强制出的六个决定

### 决定 1：**空**、**零**、**未知**、**不适用** 是四种不同的事实

名实相符要求名称说明事实。因此这四种状态必须分别表达：

| 事实 | 表达 | 不得 |
|---|---|---|
| 没有数据 | 空态 + 明确入口 | 空白 |
| 值是 0 | 显示 `0` | 与空混同 |
| 不知道值 | 「未知」或「待核实」 | 显示 0、空白或失败 |
| 该值不适用 | 明确不适用 | 与未知混同 |

**这是展示族最容易被忽略、后果最重的一条**：把「未知」显示成 0，会让读者基于错误事实决策。

### 决定 2：围合必须由**独立身份**决定

相成相制 + NG4：卡片用于需要独立边界的对象。

**删去检验**：去掉边框后内容关系不变，则不应围合。

**推出**：本族需要「围合」与「仅用间距组织」两种能力并存，二者由内容的独立身份决定，不由视觉偏好决定。

### Card 当前的线、面与阴影

Card 当前默认同时有 1px border、bg-card 与 shadow-panel，圆角读取 `--qy-radius-panel`（12px）；没有默认 padding、标题槽或布局。它的线与面是当前**选择**，不能从独立身份推出必须同时有三种机制。

**默认阴影的独立用途未证，UNVERIFIED。** 尚无有/无阴影的真实组合比较来说明阴影在已有线与面之外承担什么必要作用，保留现值不等于关系推导。`--qy-shadow-panel` 的浅色值为 `0 1px 2px`（黑色 4%）加 `0 4px 12px -8px`（黑色 12%），深色同几何分别 20% / 24%；参数均为**预设**，不写成理念必然。

Card 默认 div 不强制可聚焦；render 为链接等焦点入口时，边框**只变色不加粗**，没有额外内描边或外围圈。强制颜色由 styles.css 统一回退，见基础层 §15。独立子 Button 保持自己的 6/7/8px 角色，不因被放进 Card 就套同心公式；只有同一承载轮廓等距内缩适用，见基础层 §4。

### 决定 3：比较任务**必须保留二维关系**

布白有用：比较需要并置。

**禁止**：为了窄屏或为了「简洁」而隐藏必要的比较列。窄屏改的是**承载方式**（并置→逐条，或横向滚动），不是删除比较维度。

### 决定 4：刷新**保留**仍然有效的工作面

进退相承：已有内容的刷新不应无故卸载有效内容。

**禁止**：用骨架屏替换真实内容。加载时保留旧内容并如实标记其状态。

### 决定 5：关系间隔与工作空间是两个决定

布白有用：字段之间的关系间隔、可工作的内容空间、判断余地分别安排。

**推出**：表格行高、单元格内边距、列间距各有角色，不用一个数值统管。

### 决定 6：概要到深入有理由，且有返回

展开有据：详情、展开行、树节点都要有返回。

**禁止**：直达详情无法返回；关键信息只在悬停提示里。

## 四、本族的单元构成

族目标按**承载的关系**分组；当前 Card / Separator 之外的成员待重写，不沿用旧实现的文件行数作为现状：

| 分组 | 成员 | 承载的关系 |
|---|---|---|
| **围合与分节** | `Card`、`Separator` | 独立边界；分节 |
| **表格与集合** | `Table`、`DataTable`、`ScrollArea`、`VirtualList` | 二维比较；长集合的可达 |
| **条目** | `Item`、`DescriptionList`、`Timeline`、`Steps` | 有序/无序的条目关系 |
| **标记** | `Badge`、`Kbd`、`Avatar` | 短标记；身份样本 |
| **度量** | `Stat`、`Meter`、`Chart` | 数值；测量值；数据关系 |
| **状态** | `Empty`、`StatusDot` | 无内容；对象状态 |
| **层次** | `Tree` | 层级关系与展开 |

**边界说明**：

- `StatusDot` 在动作族已列为状态指示。**归属展示族**（它承载理解，不触发改变）；动作族的引用应移出。
- `Meter` 表达**测量值**（如磁盘占用），`Progress` 表达**任务进度**。二者语义不同，不得互换（design.md 原文已区分）。
- `VirtualList` 是新增 Primitive，承载长集合的可达与渲染边界。

## 五、逐组件定位与关键取舍

| 组件 | 定位 | 关键取舍 |
|---|---|---|
| `Card` | 有独立身份的内容边界 | **不提供「都要套卡」的便利**：不因放进去就自动获得内边距与标题结构，避免诱导 NG4 |
| `Separator` | 分节线 | 是关系标记，不是装饰；有分节需求才用 |
| `Table` | 二维比较（静态） | 保留列关系；窄屏横向滚动而非删列 |
| `DataTable` | 二维比较（可排序、可筛选、可选择） | 排序/筛选状态属于**应用**；组件不推断业务状态 |
| `ScrollArea` | 长内容的可滚动承载 | 滚动条是必要信息（可滚动性可见） |
| `VirtualList` | 超长集合的可达性 | 虚拟化不得破坏键盘可达与焦点保持 |
| `Item` | 列表条目（可含附属动作） | 条目身份由内容决定，不由外观 |
| `DescriptionList` | 名称—值对 | 值可为空/零/未知（决定 1 的落点） |
| `Timeline` | 按时间的条目序列 | 时间顺序是事实，不排序美化 |
| `Steps` | 流程位置 | 当前步是**应用**的事实 |
| `Badge` | 短标记 | 不承担状态语义；状态用 `StatusDot` |
| `Kbd` | 键位显示 | 纯展示 |
| `Avatar` | 身份的视觉样本 | 必须有可访问名称；图像失败有回退 |
| `Stat` | 单个数值读数 | 数值 + 单位 + 变化方向各自成事实 |
| `Meter` | 测量值 | 与 `Progress` 区分 |
| `Chart` | 数据关系 | 承载面、轴、图例、空态、无障碍需共同契约 |
| `Empty` | 无内容 | 必须给出入口，不只是说明 |
| `StatusDot` | 对象状态（含等待/未知） | 状态由应用给；颜色不是唯一信息 |
| `Tree` | 层级与展开 | 展开有返回；选中与展开是两个状态 |

## 六、这一族最容易做错的六件事

| # | 错误 | 违反 | 判据 |
|---|---|---|---|
| 1 | 把「未知」显示为 0 或空白 | 名实相符 | 用四种数据替换同一位置，显示是否不同 |
| 2 | 为窄屏删掉比较列 | 布白有用 | 窄屏下比较任务是否仍可完成 |
| 3 | 每段内容都套卡片 | 相成相制 / NG4 | 去掉边框后关系是否改变 |
| 4 | 用骨架屏替换真实内容 | 进退相承 | 刷新时旧内容是否消失 |
| 5 | 表格行操作触发业务动作 | 归属 | 展示组件是否发请求或改状态 |
| 6 | 用 `Badge` 表达状态 | 名实相符 | 状态是否只有颜色/文字而无语义关联 |

## 七、与基础层的关系

消费 §3（间距角色：关系间隔与工作空间分开）、§4（圆角与独立子对象）、§6（表面层级与阴影的未证用途）、§7（颜色角色：图表系列仅用于数据）、§8（文字档）、§9（状态归属）、§13（密度：紧凑不缩小文字）、§15（可聚焦 Card 边框只变色）、§16（对比：图形信息 ≥3:1）、§17（内容容量）、§18（组合契约）。所有编号指向[基础层](2026-10-03-foundation.md)。

**本族不新建数值。**

## Alternatives

**未把 `StatusDot` 留在动作族。** 它承载理解（这个对象现在怎样），不触发改变。放在动作族会诱导把它当作可点击的状态开关。

**未删除 `Meter` 而与 `Progress` 合并。** 测量值与任务进度是两个语义：前者是「现在占了多少」，后者是「还要多久」。合并会让「磁盘 80%」与「上传 80%」用同一个组件，而它们的含义与更新方式不同。

**未给 `Card` 提供默认的内边距与标题结构。** 那会诱导无差别套卡（NG4）。围合应由独立身份决定，不由便利决定。

**未保留骨架屏式的加载。** 假内容不说明事实，且与「刷新时保留有效工作面」冲突。加载状态由 `aria-busy` 与内容保留共同表达。

**未把排序/筛选状态放进 `DataTable`。** 那属于应用（范围、条件、结果），组件只呈现。

## Consequences

- Card 当前没有自动内边距与标题槽，内容布局由组合给出；其默认阴影独立用途继续记 UNVERIFIED，需真实组合比较。
- `Table` / `DataTable` 需要确立窄屏承载规则（横向滚动 vs 逐条），并在文档站给出示例。
- `StatusDot` 归入展示族后，动作族文档中的引用需改。
- `VirtualList` 为新增，`ScrollArea` 需要与之明确分工（滚动容器 vs 虚拟化）。
- `Meter` 与 `Progress` 的文档需要明确二者的判据，避免误用。
- 待重写成员与文档按当前归档状态逐项恢复；族目标清单不代表现有组件页数量或完成证据。
