# 理念驱动改造与并行实施

状态：Accepted（用户于 2026-10-02 明确指示执行）。范围：Qingye UI 本仓库。

## Context

公开理念 v2、内部定义 v2.1 与现有组件库已形成完整改造计划。用户确认默认辨识度、双样例和官网叙事后，拒绝三个具体视觉提案，并要求视觉后置、先依新规范并行实施。

- [旧提案与拒绝状态](../plans/2026-10-02-design-options/manifest.json)。
- [方法入口](../../design.md)与 [实现规范](../../STANDARDS.md)。

## Decision

视觉选图不作为代码前置。设计方法、组件语义、状态真实性、修改归属和可访问性继续约束实现。coss 是可替换来源，保留/适配/自建依据真实缺口，底层无障碍原语单独评估。主 agent 下发并审核，多个 GPT-6.1 sol / xhigh 子 agent 按文件所有权并行，集成依赖与浏览器生命周期串行管理。

## Alternatives considered

- 等待图片通过再实施：与用户明确后置视觉的要求冲突。
- 全库无证据重写或保留 coss 结构作为最高目标：两者都不能保证遵循任务与状态定义。
- 各 agent 自行构建第二套索引或浏览器：会带来事实漂移、重复验证与生命周期冲突。

## Consequences

保持 88 模块、六模式、工具/Studio、官网/AI 资料和验收的完整范围。拒绝图仅作历史记录；默认视觉实际变更单列，最终视觉定稿仍为后置事项。现有规范中默认外观偏好不再被解释为所有产品的硬限制。

## Verification

按 [执行记录](../implementation/2026-10-02-execution.md)分别登记静态、组件、浏览器、包消费和人工证据；缺口不能记为通过。没有实现或运行证据时不将计划状态当完成。

## Revisit when

用户明确调整目标、实际消费契约出现冲突、公开材料发生事实变化，或共享工具/状态边界不能支持完整任务时，依据具体证据修订此决策。
