# 日期与时间族判据

## Status

Proposed（2026-10-03）。七族判据第六份。依据 [design.md](../../design.md)、[基础层](2026-10-03-foundation.md)、[组件分层](component-layering.md)。

## 一、这一族处理什么真实问题

一个人要**给出一个时间点或一段时间**，而这个时间**有时区、有历法、有「相对现在」的含义**。

不是「选个日期」，是：选定一个具体的日子、选定一段区间的起止、选定精确到时刻的时间，并且**这些值在跨越时区、跨越夏令时、跨越午夜之后仍然指的是同一件事**。

**核心问题**：如何让「用户的时间意图」与「系统存储的时间事实」之间不产生歧义。

## 二、参与的与不参与的方法

| 方法 | 参与 | 在这一族的后果 |
|---|---|---|
| 名实相符 | **主导** | 日期、时间、区间、时区各自说自己的事实；**不确定的输入不得被静默补齐** |
| 随境取度 | **主导** | 输入方式随环境变化（键入 / 选择 / 原生），**值不变** |
| 展开有据 | **参与** | 日历展开有理由；已选可回看；可直接键入 |
| 进退相承 | **参与** | 部分输入、无效输入、清除、区间反向都由同一对象承接 |
| 相成相制 | **参与** | 起止端点互相约束；约束不能只写在文档里 |
| 布白有用 | 不参与 | 日历格子的空间由历法决定 |

## 三、由关系强制出的七个决定

### 决定 1：**不完整输入**不得被静默补齐

用户输入 `2026-10`，不等于 `2026-10-01`。

| 输入 | 成立的事实 |
|---|---|
| 只有年 | 只知道年 |
| 只有年月 | 只知道年月 |
| 完整日期 | 完整的日期 |

**禁止**：把部分输入静默补成完整日期。那会用一个用户没给的默认值产生一个具体的值。

**推出**：部分输入要么被明确拒绝，要么按应用策略处理，但**组件不得自行补齐**。

### 决定 2：**区间的端点顺序**是事实，不是错误

用户先选结束日期可以发生。两种处理都是合法的，但**必须明确**：

- 视为反向并交换 → 必须在界面上可见
- 视为无效并提示 → 必须能修正

**禁止**：静默交换后不告知。那会改变用户输入的意图。

### 决定 3：**「今天」是环境事实，不是常量**

「今天」随日期变化、随时区变化。

**推出**：
- 「今天」必须由**运行时**给出，不得由组件在初始化时固定
- 跨午夜时「今天」的标记要能更新（或明确说明不更新）
- 不得把「今天」写进任何持久化的值

### 决定 4：**相对日期与绝对日期是不同的表达**

「3 天后」与「2026-10-06」在跨时区时不等价。

**推出**：组件的值始终是**绝对时刻**（或明确的本地日期），「相对」只是显示层的表达。换算规则由应用定义。

### 决定 5：**禁用日期**必须能说明理由

一个日子不可选，用户有权知道为什么（超出范围、已被占用、不可用）。

**禁止**：只是灰掉。灰色的日子既不说原因，也不能用颜色以外的方式区分（无障碍要求颜色不是唯一信息）。

### 决定 6：**键盘与直接输入必须可用**

展开有据要求「支持直接抵达」。日历是选择器，**键入必须是等价路径**。

**推出**：每个日期组件必须能用键盘完成同样的输入，且不必经过日历格子。

### 决定 7：**原生能力在需要时保留**

不同浏览器与平台的日期输入能力不同（原生选择器、自动填充、辅助技术）。

**推出**：不假定日期输入只能通过自定义日历完成；在合适的情境允许原生输入路径。这与选择器族决定 5 同源。

## 四、本族的单元构成

| 组件 | 承载的关系 |
|---|---|
| `Calendar` | 历法上的位置选择（单日、多日、区间） |
| `DatePicker` | 单个日期的输入与选择 |
| `DateRangePicker` | 一段区间的输入与选择 |
| `DateTimePicker` | 日期 + 时刻 |

**四者的关系**：`DatePicker` / `DateRangePicker` / `DateTimePicker` 都是**输入控件**（属选择器族语义），`Calendar` 是**承载**它们选择行为的日历视图。

**推出**：`Calendar` 可以独立使用（如嵌入式日期总览），但三个 Picker **必须能键入**，不强制走日历。

## 五、逐组件定位与关键取舍

| 组件 | 定位 | 关键取舍 |
|---|---|---|
| `Calendar` | 历法位置选择 | 键盘导航完整；禁用日有理由；「今天」来自运行时 |
| `DatePicker` | 单日期输入 | 部分输入不静默补齐；可键入 |
| `DateRangePicker` | 区间输入 | 端点反向可见；起始与结束各自可清除 |
| `DateTimePicker` | 日期 + 时刻 | 时区策略必须由应用声明；组件不猜 |

## 六、这一族最容易做错的六件事

| # | 错误 | 违反 | 判据 |
|---|---|---|---|
| 1 | `2026-10` 被补成 `2026-10-01` | 名实相符 | 部分输入是否产生了用户没给的值 |
| 2 | 区间端点静默交换 | 名实相符 | 交换是否可见 |
| 3 | 「今天」在初始化时固定 | 名实相符 | 跨午夜后标记是否正确 |
| 4 | 禁用日期只有灰色 | 无障碍 / 名实相符 | 是否能知道为什么不可选 |
| 5 | 只能通过日历格子输入 | 展开有据 | 键盘能否不经格子完成输入 |
| 6 | 时区由组件假定 | 名实相符 | 跨时区后同一输入是否指同一时刻 |

## 七、与基础层的关系

消费 §1/§2（控件几何）、§5（边界）、§8（文字档：日历格子的数字用 `numeric`）、§9（状态归属：选中是组件自持，**但时区与相对时间策略归应用**）、§12（动效：日历浮层归 `motion.css`）、§14（方向与语言：**日历的周起始日与 RTL 需专门处理**）、§15（键盘导航：日历是重点）、§17（内容容量：部分输入与未知）。

**本族不新建数值。** 需要时回基础层补。

**本族的本地化要求高于其他族**：周起始日、日期格式、历法在不同语言下不同。这是 §14 的落点，必须在重写时单独验证。

## Alternatives

**未把 `Calendar` 与三个 Picker 合并。** 日历是承载，Picker 是输入控件。合并会让「只需要键入一个日期」的场景被迫加载日历。

**未统一时区处理。** 时区是应用的事实，不是组件的默认。组件必须接受应用声明的时区策略，不能自行假定。

**未把禁用日期做成纯视觉状态。** 颜色的可用性有限，且不说明原因。

**未移除键入路径。** 展开有据要求直接抵达；日历是辅助，不是唯一入口。

## Consequences

- 四个组件都涉及本地化与历法，重写时必须按 §14 单独验证周起始日、格式与 RTL。
- `date-range-picker`（406 行）此前在窄屏发现过真实溢出问题（见 `docs/baseline/2026-10-01-ci-date-range-failure/`），重写时必须以该场景为验收之一。
- 部分输入的处理策略需要新增到 `Field` 的契约中（表单族），因为它是字段级的校验事实。
- 时区策略需要在文档中明确由应用声明，并给出示例。
