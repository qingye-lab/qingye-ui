# 表单族判据

## Status

Decided for Input（2026-10-03，按逐值裁决修订）；其余重写目标为 Proposed。当前本族保留 Input、Field、Fieldset，表中其他控件是待重写的族目标，不表示已导出。Field / Fieldset 为保留实现，不能把其现有数值写成新设计的推导。

依据：[design.md](../../design.md) 的六种方法与设计契约，[基础层](../decisions/2026-10-03-foundation.md) 的 18 项，[组件分层](../decisions/component-layering.md) 的归属。

**本文的写法**：从**任务**出发，推到组件必须长成的样子。不从现有组件反推。凡属项目预设而非关系推导的，标注「预设」。

## 一、这一族处理什么真实问题

一个人有一个值要给出去，而这个值**可能不对、可能给不出去、可能给了但不知道成没成**。

不是「填一个表单」，是：标出一个字段的含义、输入一个值、在值不对时知道哪里不对、在给不出去时知道为什么、在结果未知时知道要核实。

**于是这一族面对的核心问题**：如何让「值的真伪」与「值是否送达」两件不同的事实**同时可读，且互不冒充**。

## 二、参与的与不参与的方法

| 方法 | 参与 | 在这一族的具体后果 |
|---|---|---|
| 名实相符 | **参与** | 字段名称、值、错误、结果**各自只说自己那一件事**；四种事实不得混为一谈 |
| 相成相制 | **参与** | 名称、说明、输入、错误**必须共处**并互相约束；错误要能指向具体字段，名称要能随错误调整 |
| 进退相承 | **参与** | 输入中、校验失败、提交等待、**结果未知**、已保存围绕**同一个值**发生 |
| 布白有用 | 参与（有限） | 字段内的关系间隔与字段间的关系间隔是两个决定 |
| 随境取度 | 不参与 | 输入控件不决定自己的承载方式；窄屏改的是密度与命中区，不改字段语义 |
| 展开有据 | 不参与 | 字段不展开信息；把说明藏进 Tooltip 是误用 |

## 三、由关系强制出的四个结构决定

### 决定 1：名称、输入、错误是一个**不可拆分**的单元

相成相制要求四者互相约束，而互相约束的前提是**它们在同一结构里**。

由此：字段不是「一个输入框旁边放个错误文字」，而是**一个具有共同语义与状态的单元**。分开后名称不知道错误是什么，无法在出错时调整措辞；错误不知道名称是什么，无法指明对象。

**这不是表单惯例，是关系要求。** 违反它的写法（把错误放在表单顶部、用 Toast 报告字段错误）在本体系里不成立。

### 决定 2：错误归属**就地**，不新增组件

错误要指向对象，就必须与对象同处（决定 1）。**因此错误不是独立组件，是该单元的部件。**

现有 `FieldError` 已经做对这件事：它在 `Field` 上下文内跟随校验状态，在上下文外只渲染给定内容。**保留它，不新增 `field-error`。**

（初版 `component-layering.md` 把它列为新增项，是未核实就下的判断。已修正。）

### 决定 3：**值的真伪**与**是否送达**必须分开表达

这是本族最重要的一条，也是当前实现最缺的。

| 事实 | 谁产生 | 表达在哪 |
|---|---|---|
| 值不符合规则（必填、格式） | 应用/浏览器校验 | 字段的错误位 |
| 值已提交，等待响应 | 应用 | 字段或所在动作的状态 |
| **已提交，但结果未知** | 应用 | **必须有独立表达** |
| 值已确认保存 | 应用 | 已保存状态 |

**禁止**：把「提交失败」与「结果未知」显示成同一种错误。超时不等于未执行，也不等于失败。

**禁止**：控件自行判断。输入框不知道服务端发生了什么。

### 决定 4：字段的三种关系间隔是三个决定

| 关系 | 角色 | 不是 |
|---|---|---|
| 名称 ↔ 输入 ↔ 错误（同一字段内） | `--qy-field-gap` | 不是普通间距 |
| 字段 ↔ 字段 | `--qy-field-group-gap` | 不是 field-gap 的倍数 |
| 同一组动作 ↔ 动作 | `--qy-action-gap` | 不决定动作组到字段的距离 |

## 四、这一族的单元构成

推到具体，表单族由三类东西组成，**层次不同**：

| 类 | 成员 | 层 | 它是什么 |
|---|---|---|---|
| **单元** | `Field` + 部件 | Primitive | 一个值及其全部事实 |
| **容器** | `Form`、`Fieldset` | Primitive | 一组值的共同上下文与提交 |
| **控件** | `Input`、`Textarea`、`Select`、`Combobox`、`Checkbox`、`Radio`、`Switch`、`Slider`、`NumberField`、`OtpField`、`TagInput`、`NativeSelect` | Primitive | 值的输入方式 |

**关键**：控件是**可替换的**——同一个 `Field` 里可以放 Input、Select 或 Slider，而名称、说明、错误的行为不变。这就是决定 1 的验证：**换控件不该改变字段的事实结构。**

## 五、族内每个组件的定位（逐项）

| 组件 | 一句话定位 | 关键取舍 |
|---|---|---|
| `Field` | 一个值及其名称、说明、错误、状态的共同结构 | 当前有 vertical / horizontal 方向选择，不判断业务事实 |
| `FieldGroup` | 一组字段的纵向关系 | 只给关系间隔，不围合 |
| `FieldLabel` | 值的名称 | 名称是值的属性，不是装饰文字 |
| `FieldDescription` | 帮助理解该值的事实 | 与错误分开，不互相替代 |
| `FieldError` | 值不符合规则的地点 | **保留现有实现**；不改容器，不新增组件 |
| `FieldItem` | 名称旁的附属事实（如可选标记） | — |
| `FieldContent` | 横向字段的内容列 | 仅为 `horizontal` 服务 |
| `FieldSeparator` | 字段组之间的分界 | 有分界需求时才用，不替代间距 |
| `FieldControl` / `FieldValidity` | 无障碍原语的两个出口 | 直接转出，不包装 |
| `Form` | 原生提交范围与重置上下文 | 使用原生 onSubmit / FormData；平台约束由 noValidate 控制，应用显式提供 Field.invalid 与就地 FieldError，不发请求、不分发或推断校验/结果事实 |
| `Fieldset` | 一组相关字段的共同名称 | — |
| `Input` | 单值文本输入 | 吸收原 `search-input`、`password-input` 为形态，不独立成组件 |
| `Textarea` | 多行文本输入 | 与 Input 共享边界规则；`field-sizing-content` |
| `NativeSelect` | 平台原生选择语义 | 保留下拉原生行为（表单提交、移动端选择器） |
| `Select` / `Combobox` / `Autocomplete` | 从选项中选择 | 三者差别在选项来源与是否可输入，判据见选择器族 |
| `Checkbox` / `Radio` / `RadioGroup` / `Switch` / `Toggle` | 二值或集合选择 | 选中是**控件自持**状态，可由应用受控 |
| `CheckboxGroup` | 一组复选框的范围 | 范围是集合语义，非布局 |
| `Slider` | 在区间内取值 | 拖拽中保留值；不做「猜测的进度」 |
| `NumberField` | 数值输入与步进 | 步进是结构，不是装饰按钮 |
| `OtpField` | 分段固定长度输入 | 独立状态机：分段、粘贴、自动推进 |
| `TagInput` | 集合输入 | 表达集合而非单值；标签是已确认项 |
| `Label` | 通用可访问名称入口 | 字段内优先用 `FieldLabel` |

## 六、这一族最容易做错的五件事

| # | 错误 | 违反 | 判据 |
|---|---|---|---|
| 1 | 用 Placeholder 承担字段名称 | 名实相符 | 输入后名称消失，用户失去对象 |
| 2 | 把「结果未知」显示为「失败」 | 进退相承 | 超时后显示失败，用户重复提交 |
| 3 | 校验失败清空输入 | 进退相承 | 失败后草稿丢失 |
| 4 | 用 Toast 报告字段错误 | 相成相制 | 提示消失后无法确认哪里错 |
| 5 | 换控件时名称/错误行为改变 | 相成相制 | 同一字段从 Input 换 Select，错误位置变了 |

## 七、新增与删除（本族）

**删除**：`search-input`、`password-input`（并入 `Input` 的形态）。

**不新增**：`field-error`（已存在，见决定 2）。

**当前已实现**：Input 使用 `type="search"` 与 `type="password"`。搜索形态带清空入口，密码形态可切换可见性；clearable、visibilityToggle 等入口可调整默认行为，render 与原生 input 语义保留。过滤/搜索请求仍由应用或 Pattern 承担。

> **2026-10-10 修订（用户裁决「功能要纯粹」）**：上面两段已不是现状。Input 只承载值，不再内置清空、搜索图标与显示密码；`search-input`、`password-input` 重新成为独立组件，但不是另写一套输入，而是由 InputGroup + Input + InputGroupButton 组合。普通字段需要附属动作时直接用 InputGroupButton。见基础层「2026-10-10 功能纯粹：本次梳理的处置」。

### Input 的当前几何与焦点

五档 xs/sm/md/lg/xl 使用同名 text-control 档，桌面每侧垂直视觉余量为 4/5/6/6/7px。外高与文字值为**预设**，余量由所选外高与行高换算；lg/xl 曾借低一档文字只增加空白，当前已接入同名档，见基础层 §1、§2、§8。

Input 的 1px 边框属于外层共同边界，实际 input 透明。**聚焦只改变边框颜色，不加粗、不增加内描边或外围圈**：普通态读 ring，invalid 聚焦读危险文字色，错误事实仍由 aria-invalid 声明。当前浅色输入边框为黑色 alpha 50%，深色为白色 alpha 44%，不从默认 alpha 推断任意承载面达标。

清空与密码可见性按钮是独立焦点部位，当前在各自盒内画 2px 线；不能把输入主体只变色误写成附属按钮也没有信号。强制颜色由 styles.css 统一恢复系统 outline，详见基础层 §15。touch-target 在粗指针下自建定位上下文；输入外高的 44px 库内目标与附属动作的命中层分别核对。

Input 的内建文案来自 locale。className / style / render 属于真实输入，controlClassName 是共同边界样式入口；unstyled 为调用方已有共同边界的组合保留语义，不等于删除可辨认机制。

## 八、与基础层的关系

本族消费基础层的 §1（内部几何）、§2（尺寸）、§3（间距角色）、§5（必要识别，描边为可选机制）、§7（颜色角色，含 `danger`）、§8（同名控件文字）、§9（状态词汇与归属）、§15（焦点只变色与命中）、§17（内容容量：空/零/未知/不适用）、§18（组合契约）。所有编号指向[基础层](2026-10-03-foundation.md)。

**本族不新建任何数值。** 若实现时需要新数值，回基础层补。

## Alternatives

**未把错误做成独立组件。** 错误必须与对象同处（决定 1），独立组件无法保证这一点，且会诱导「表单顶部集中显示错误」这类脱离对象的做法。

**未把 `search-input` 保留为组件。** 它的语义仍是「输入文本」，搜索行为属于 Pattern。保留会让「输入框」这一语义出现多个名字。

**未让字段自持提交结果。** 控件不掌握请求结果；应用给出的布尔忙碌状态或联合状态都可成立，不能以 API 类型代替事实归属检查。

**未引入「表单布局」组件。** 布局是 Pattern 的职责，字段单元只给关系间隔。

## Consequences

- Field 当前的部件与原语出口以源码为准；FieldTitle、方向选择与 FieldError 的显式内容入口也须如实描述，不沿用旧部件数量代替核对。
- Input 当前已支持搜索与密码形态；后续文档和组合使用当前入口，不把已归档的独立组件当作现有 API。
- 「结果未知」的表达需要 `pending-value`（Primitive，见 `component-layering.md`）与本族的组合，试点时确认接口。
- 本族的 API 破坏性变更：`Field` 若引入「值的送达状态」入口，所有使用处需要传值。范围与形式在试点中确定。
- 本文是其余六族的模板。若其余各族按此深度产出后出现形式不适用的地方，回改本文并说明。

## 九、补：`InputGroup`

`InputGroup` 是**输入与附属元素的共同结构**：输入区 + 前置/后置的标记、按钮、单位。

它不是布局组件，因为它**改变输入的可访问语义与焦点顺序**（附属元素属于该输入的关系）。因此归本族。

| 决定 | 内容 |
|---|---|
| 输入区仍是可编辑区 | 基础层 §5：必要识别机制存在，描边不是唯一机制 |
| 附属元素不得吞掉输入焦点 | 基础层 §15 |
| 附属按钮属动作族语义 | 危险后果可见且与按钮可关联；共同结构或已有非空说明均可（动作族决定 3） |
| 内嵌按钮的圆角 | 仅同一承载轮廓等距内缩时换算并钳制非负；独立子对象不适用，基础层 §4 |

InputGroup 当前已归档，本节是重写契约；Input 自身已有搜索/密码附属部位，不表示 InputGroup 已恢复。

**与 `Group` 的区别**：`Group`（布局族）只组织位置与间隔；`InputGroup` 参与输入语义。
