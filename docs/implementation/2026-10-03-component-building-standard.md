# G0 · 组件构建标准

适用于 `@qingye/ui` 的 88 个组件独立重写。设计判断依据根目录 [design.md](../../design.md)，实现约束依据 [STANDARDS.md](../../STANDARDS.md)，尺寸归属依据 [CLAUDE.md](../../CLAUDE.md)。

语义、状态归属、可访问行为、属性透传、国际化与主题轴是硬要求。表面配方、尺寸数值、圆角、字重与曲线是当前默认预设；调整预设须集中修改、列出影响并验证消费部位，不能在单个组件里制造另一套规则。

## 1. 推导起点

写代码前提交下表的答案。答案须包含真实使用情境、状态来源与检查动作；缺少决定性事实的项记为 `UNVERIFIED`，不得用旧组件外观补答案。

| 问题 | 答案须确定什么；评审怎样检查 | 不可接受的答案 |
|---|---|---|
| 它代表什么对象、动作与后果？ | 指出操作对象、范围和可观察结果；用名称与事件逐一核对。Tabs 切换面板，Select 选择值，Menu 执行命令，Progress 表达进度，Meter 表达测量值 | “一个好看的选择器”；把不同动作都叫“确定” |
| 哪些方法参与这次判断，为什么？ | 每个相关方法对应一个具体取舍及其后果，见下表；普通组件只回答相关问题 | 把六个方法写成标签；为装饰图案补文化解释 |
| 哪些部件不可删？ | 删除后，理解、执行、保护或协调的哪一项受损；若已有可靠机制承担同一作用，复用它 | “其他库也有 Header”；每段文字都增加一个容器 |
| 哪些状态必须存在，由谁持有？ | 列出事件、状态来源、受控入口和退出条件；本地展开与持久选择分开 | “点击后变绿就是成功”；让 UI 猜权限或请求结果 |
| 哪些内容必须同时出现？ | 用真实任务检查比较列、输入、必要后果与恢复入口；说明哪些可以展开 | 为窄屏隐藏必要比较列；唯一后果只放 Tooltip |
| 布局、语言、密度或主题变化后什么必须保留？ | 列出对象身份、草稿、选中范围、焦点、阅读位置、返回线索；逐项变化后复查 | 断点切换时重建表单；换主题改变权限 |
| 哪项差异属于哪一层？ | 公共语义与基础交互归库；重复任务组合与品牌归项目；权限、路由、版本、请求与持久化归应用 | 在基础控件里读会话；在页面复制基础控件 |

| 方法 | 组件作者要作的决定 | 可观察结果 |
|---|---|---|
| 名实相符 | 部件名称、动作名称与状态事件是否对应同一事实 | 名称能区分对象与后果；等待、失败、未知不显示成完成 |
| 相成相制 | 内容、说明、动作与保护各承担什么作用；谁在当前任务中需要强调 | 异常时可突出停止；视觉强度不决定权限或风险 |
| 布白有用 | 哪些间隔表达关系，哪些空间承接编辑或比较，哪些内容确有独立边界 | 收紧间距后关系仍可辨；移除无身份卡片不损失信息 |
| 随境取度 | 指针、触摸、慢响应、失败与窄屏各需要怎样的承载方式 | 必要反馈仍可找到；重排不丢输入或焦点 |
| 展开有据 | 什么需要预览、深入、直接抵达与返回 | 高频动作可直接执行；必要后果无需猜测或悬停 |
| 进退相承 | 等待、失败、未知、取消与恢复如何围绕同一对象发生 | 失败保留有效草稿；关闭与撤销、取消请求与取消完成可区分 |

## 2. 解剖（anatomy）约定

部件是公共组件内可指认的职责，不能只因 DOM 多一层而获得名称。依据设计契约的删去、分工、变化、来源与归属检验确定边界。

| 决定 | 推导与规则 | 评审检查 |
|---|---|---|
| 复用既有部件 | 同一语义、状态与可访问关系已有公共实现时，先用其属性、组合或 `render`；外观相似不足以证明职责相同 | 说明被复用的职责；没有为“少写一点代码”把命令伪装成选择 |
| 增加部件 | 需要独立内容入口、状态表达、语义关联或稳定样式入口，且删去会损害任务时才增加 | 每个公开部件均能指向缺失的能力；不能只回答“方便加 padding” |
| 一个组件带部件 | 部件共同完成一个公共语义，依赖同一交互模型或上下文；离开该关系便失去职责，例如触发器与其弹出内容 | 键盘、关联 ID、焦点返回与状态转换能在同一契约中说明 |
| 两个组件 | 两者能独立命名和使用，拥有各自完整语义与状态契约，仅在某个任务里组合 | 单独使用仍成立；组合由项目或公共组合层承接，不能藏进基础组件 |
| 部件命名 | 按职责命名 `Root`、`Trigger`、`Popup`、`Label`、`Description`、`Indicator` 等；名字须匹配实际行为；新增职责不用颜色、位置或装饰名称 | `Trigger` 真能触发；`Description` 真关联说明；RTL 与布局变化后名称仍成立 |
| 文件边界 | 一个公共组件家族一个 kebab-case 文件，相关部件同文件；独立公共组件才另开文件 | 不把每个 DOM 层拆成文件，也不把独立控件塞进另一组件 |

每个可样式化的实际部件必须有稳定 `data-slot`，包括根、可定位的状态图形与浮层。子部件用 `<component>-<part>`；根沿用库内简写 `<component>`，也可明确用 `<component>-root`，同一组件确定一种。名称取职责，不取 `left`、`blue` 或当前 DOM 层数。检查时逐一对应部件表、实际节点、样式与测试定位；布局重排不得随意改名。

纯上下文、Fragment 不产生节点，不强造 slot。仅为布局存在的内部节点若有独立样式或动效，也必须给出职责明确的 slot，但不因此增加公开部件 API。伪元素属于宿主的表面或命中区，不为它另造公开部件；检查其样式是否可由宿主 slot 控制。

`data-slot` 不是 ARIA role，也不代替名称或状态。组件的公开 props 必须透传 `id`、`aria-*`、`data-*`、事件、`style` 和 `ref`；组合层覆盖同名 slot 时须能指出新的部件身份。评审用实际渲染节点核对，不能只看接口声明。

外部类最后进入 `cn(内部类, className)`，使项目表达在公共默认值上调整；Base UI 的 `className` 回调先用实际原语状态求值，再最后合并。改变宿主用 `render`：已有原语直接转交其 `render`，自建宿主用 `useRender` 与 `mergeProps`，不新增 `as`。合并事件时使用原语的约定，不用对象展开覆盖内部处理器；`mergeProps` 不合并 ref，多个 ref 须另用实际可用的合并机制。检查替换元素后的原生语义、事件与 ref，不把类型通过当作语义通过。

## 3. 表面层级

表面描述内容与周围的关系，不描述业务重要性。层级不是六个从暗到亮的固定台阶：`popover` 与 `surface-raised` 当前绑定同一 token，`muted` 是随底色合成的内嵌层。先判关系，再选角色；亮度、边框与阴影由集中主题实现。

| 表面类 | 当前 token | 用于什么关系 | 给定内容的选择检验 |
|---|---|---|---|
| `bg-background` | `--qy-background` | 页面持续工作面，没有另立边界的正文与分节 | 内容属于页面本身，标题、对齐与间隔即可组织时，不追加卡片 |
| `bg-card` | `--qy-surface` | 有独立身份的面板，或需要稳定可读底面的输入工作区 | 对象能独立识别、排序或操作时可围合；输入需要可辨编辑面时可取此底色，不能据此给整个表单套卡片 |
| `bg-popover` | `--qy-surface-raised` | 临时浮起、与触发对象有关的阅读或操作面 | 内容由触发器打开，须定位、避让与返回焦点时使用；颜色本身不建立这些行为 |
| `bg-surface-subtle` | `--qy-surface-subtle` | 持续、从属的区域底面，不另宣称独立对象或临时浮层 | 需要辨认侧区或辅助区域，且可由整体结构解释其从属关系时使用；不能代替禁用状态 |
| `bg-surface-raised` | `--qy-surface-raised` | 相对承载面浮起的局部工作面，例如内嵌轨道中的选中项 | 内容仍在原有结构内，只须表示局部层次或当前项时使用；不因背景相同就赋予 Popover 语义 |
| `bg-muted` | `--qy-surface-inset` | 内嵌承载区或轨道，让其上的可操作项形成关系 | 一组项目共享承载区时可用；`muted` 不表示失败、未知或无权限 |

选择顺序：先问是否临时浮起；再问是否有独立对象边界；再问是否为内嵌承载区或局部浮起项；否则保留页面面或确有用途的从属区域。每次选择写出父表面与内容关系，浅深色都检查实际合成。删除表面后任务关系完全不变的围合，按 NG4 删除。

`STANDARDS.md` §3 的配方由下列关系决定，而不是从旧组件取样：

| 配方 | 采用理由 | 评审检查 |
|---|---|---|
| 页面略深、面板略亮；深色浮起面更亮 | 持续工作面、独立对象与浮起内容需要可分辨，不必都染品牌色 | 去掉外投影后仍可识别面板；深色浮层不会融入页面 |
| 中性叠色与角色 token | 边界、轨道、悬停层须随承载面合成；文字与必要控件边界须承担各自对比要求 | 无固定灰色；在实际支持的父表面上测对比，不只比较 token 字面值。中性色“全部半透明”的口径差异见第 10 节 |
| 容器 `border`，控件 `border-input` | 容器分组线与辨认可编辑区域的必要边界承担不同任务 | 必要输入边界不能借安静分隔线逃避可辨认要求 |
| `bg-muted inset-shadow-track` 与选中项 `bg-surface-raised` | 轨道承载一组选择，当前项从同一轨道中显现，不能像另一张独立卡片 | 取消选中后轨道仍成立；选中有真实状态，不能只靠阴影表达 |
| 内高光不拦截事件；内角跟随宿主 | 内高光说明同一个表面的边缘，不能变成第二层控件 | 伪元素 `pointer-events-none`，内角不穿出外角；点击、焦点与触摸目标不被遮挡 |
| 浅色有边框面 `bg-clip-padding`；深色背景可延伸到透明边框下 | 同一半透明边框在不同底色上的合成不同，需避免边缘发脏或断层 | 在真实父表面查看四边及圆角，而非只看正中心色值 |
| 深色输入 `bg-input/32`、悬停 `/64` | 输入面与当前指针作用需要局部反馈，不改变任务和几何 | hover 前后外框尺寸与内容位置相同；输入边界和文字仍可辨 |
| 实心按钮无外投影 | 填充已建立动作入口的区别，内高光可说明边缘；再加外投影会额外宣称浮起层级，影响同组动作关系 | 实心变体 computed 外投影为空；焦点环不因此删除 |
| `shadow-control/panel/raised/overlay` 分工 | 贴近表面的接触阴影与软尾说明不同承载关系，不能把每个表面都变成浮层 | 每个投影能对应控件、独立面板、浮层或遮罩任务；未把整套阴影统一加深 |

圆角跟随几何角色：小标记用小档，控件默认 `rounded-control`（8px），独立面板默认 `rounded-panel`（12px）。嵌套内角按实际 inset 保持同心；内高光按规范比宿主小 1px。数值是集中预设，同心关系是几何检查。评审检查嵌套角和修改角色 token 后的真实消费值，不因“都是圆角”统一所有档位。

## 4. 状态矩阵

状态不是互斥的一串皮肤。`selected + focus-visible`、`open + invalid`、`loading + disabled` 可以同时存在；组件必须说明组合优先级。选中不能吞掉焦点，无效不能清除输入，加载不能隐去动作名称。评审至少覆盖其实际可达的组合。

| 状态 | 来源与表达规则 | 评审动作 |
|---|---|---|
| rest | 无瞬时交互时仍能辨认对象与入口；rest 不代表业务成功 | 移走指针、移走焦点，检查名称、边界与当前真实值 |
| hover | 仅表达指针命中；填充或叠色改变，不改尺寸，不作为触摸端唯一入口 | 量前后几何；无 hover 时任务仍可达 |
| pressed | 表达按下的瞬时反馈，`:active` 或真实原语状态；`qy-pressable` 服从全局输入策略 | 按下、释放、移出、取消；不得在释放前宣布结果 |
| focus-visible | 键盘操作可见焦点；按钮消费 `--qy-focus-button-width/offset`，默认 2px/1px；输入消费 `--qy-focus-input-width/offset`，默认 3px/0px 与 `border-ring ring-ring/24`；不以普通 `focus:` 代替 | Tab 与方向键操作，查看环是否可见、被裁切或被其他状态吞掉 |
| disabled | 由调用方或原语规则决定不可执行；使用真实 disabled/ARIA 行为，默认 `opacity-64` 与对应指针策略 | 鼠标、触摸、键盘均不能误执行；不能只有透明度变化 |
| invalid | 实际校验事实，用 `aria-invalid` 与关联错误；默认边框 `destructive/36`，无效且聚焦时 `destructive/64` 与 `ring-destructive/16`，深色环 `/24`；组件不猜业务校验结果 | 保留原输入，错误可读、可定位；聚焦无效态仍可见 |
| loading / `aria-busy` | 表示当前区域正在处理；独立动作可保留占位宽度并显示 Spinner；动作名称不丢失 | 慢路径检查名称和几何；刷新保留有效内容与编辑。busy 不自动等于 disabled |
| selected / checked | 真实选择，使用语义适合的 `aria-selected`、`aria-checked` 或 `aria-pressed`，样式读原语对应属性；导航当前位置用适用的 `aria-current` | 受控与非受控变化均一致；选中不等于悬停或按住 |
| open | 真实展开，使用原语的展开属性及关联；本地 open 不代表已保存 | 打开、关闭、再次进入，检查焦点返回与内容连续性 |
| read-only | 值可阅读但不可编辑，语义与 disabled 分开；可选择、复制的内容不应无故不可达 | 不能改变值；仍可读取和按约定复制，不出现写操作入口 |

原语属性必须按实际 API 映射：例如某些原语的 `data-pressed` 表示持续切换值，不是鼠标按下。不得因为名字相近，把持续选择映射到瞬时反馈。无原语支持的状态由明确 prop 表达，并同步其适用 ARIA；不能只添加 `data-*`。

类别按契约确定，不按旧文件归类。`必`表示须实现并验证；`条件`表示一旦提供该能力就须实现并验证；`—`表示该语义无此状态，报告 `N/A` 与理由，不能为了矩阵造一个虚假状态。一个组件可同时属于多类。

| 类别 | rest | hover | pressed | focus-visible | disabled | invalid | loading/busy | selected | open |
|---|---|---|---|---|---|---|---|---|---|
| 执行动作的控件 | 必 | 必 | 必 | 必 | 必 | 条件：提交或输入校验关系 | 条件：承接异步动作 | 条件：可切换动作 | 条件：作为展开触发器 |
| 输入与编辑控件 | 必 | 必 | 条件：附属动作 | 必 | 必 | 必 | 条件：异步校验或加载 | 条件：可选择值 | 条件：弹出编辑器 |
| 选择与切换控件 | 必 | 必 | 必 | 必 | 必 | 条件：字段校验 | 条件：异步承载 | 必 | 条件：展开选项 |
| 导航入口 | 必 | 必 | 必 | 必 | 条件：提供禁用能力 | — | 条件：明确承接异步导航 | 条件：当前位置 | 条件：展开导航 |
| 展开与浮层家族 | 必 | 必：交互部件 | 必：触发部件 | 必：交互部件 | 必：触发部件 | 条件：组合输入 | 条件：异步内容 | 条件：含选择 | 必 |
| 展示、布局与测量 | 必 | 条件：确有交互 | 条件：确有交互 | 条件：可聚焦交互 | 条件：含控件 | 条件：展示校验事实 | 条件：展示处理中区域 | 条件：展示选择事实 | 条件：可展开 |

`STANDARDS.md` §5 的“每个交互组件必须覆盖以下状态”在此按真实能力展开：必须覆盖自己能达到的状态，条件能力不能漏测；不得让普通链接凭空拥有业务校验状态，也不得因状态属于应用而拒绝提供表达接口。

### 未完成状态的词汇与归属

| 事实 | 词汇 | 可以表达什么 | 不得推断什么；评审检查 |
|---|---|---|---|
| 尚待开始、排队或等待条件 | 等待 / waiting；当前词汇也有 `pending` | 等待对象和已知条件；能取消则提供应用授权的入口 | 等待不等于已开始。没有实际事件，不自启动进度 |
| 已开始，尚未结束 | 进行中 / `in-progress` | 真实处理、可用进度；无分母时用不定进度 | 不从计时器算出百分比；动画结束不置为完成 |
| 缺少可靠结果，尤其写入响应丢失 | 结果未知 / `unknown` | 尚未确认；应用提供的核实或恢复动作 | 超时不等于未执行或失败；不自动重试写入、不先清空草稿 |
| 已确认不能完成当前尝试 | 失败 / `failed`；部分展示词汇用 `error` | 当前失败对象、必要原因与应用提供的恢复方式 | 失败不等于草稿失效；不能把其余成功对象一并清空 |

已确认完成、部分成功和已确认取消也须按应用提供的事实表达；未开始、没有内容、零值、未知和不适用分别显示。评审用这几种数据替换同一展示位置，不能都变成空白、破折号或成功标记。

这些词汇说明事实，不要求所有组件有同名 prop 或默认字符串。草稿、范围、版本、持久选择、权限、请求开始/完成、部分成功、重试安全性与撤销结果由应用持有。组件只接受事实与回调，不发请求、不读路由、不依赖会话；评审在没有结果 prop 时触发点击，确认组件不会自称成功。

本地基础交互可以由原语持有，例如展开与暂时选择；状态型 API 同时提供受控与非受控入口及变更通知。具体命名跟随语义和原语：`value/defaultValue/onValueChange`、`open/defaultOpen/onOpenChange`，切换原语可用 `pressed/defaultPressed/onPressedChange`。评审让受控父层拒绝一次变更，UI 应保留父层事实，不能内部另存一份结果。

取消编辑、关闭窗口、请求取消后台任务、撤销已保存动作分别命名和验证；取消请求发出不显示取消完成。敏感数据或权限撤回后的清除由应用定义，布局保留规则不授予无限保留权。

## 5. 尺寸角色

| 概念 | 控制什么 | 评审测量 |
|---|---|---|
| 控件外部尺寸 | border-box 占位，角色 `--qy-control-xs/sm/md/lg/xl`；窄屏增加 `--qy-control-mobile-extra` | 真实外框高度；不能用内部 input 的高度代替 |
| 内部可用尺寸 | 外框扣除所属边框与 padding 后的编辑、图形或文字空间 | 外框、两侧边框和内边距分别记录；内外两层不能重复计边框 |
| 触摸目标 | 粗指针下的命中区域，`--qy-touch-target` 当前为 44px | 实际点按边缘，不只量可见图形；邻接目标不重叠、不被裁切 |

推导顺序是任务与控制语义不变，指针转为触摸时增加容错空间，窄屏默认控件与文字适度增大，同时保留密集桌面工作面。**加 4px 是项目选定的预设，不是从设计哲学或人体工学唯一算出的数值。** 它由 `STANDARDS.md` §2 与尺寸 token 确定；控制使用窄屏值，`sm:`（默认 640px）返回桌面值，不把触摸判断等同于屏幕宽度。

| 尺寸 | 桌面角色 | <640px 当前外高 | ≥640px 当前外高 |
|---|---|---|---|
| `xs` | `--qy-control-xs` | 28px | 24px |
| `sm` | `--qy-control-sm` | 32px | 28px |
| `default` | `--qy-control-md` | 36px | 32px |
| `lg` | `--qy-control-lg` | 40px | 36px |
| `xl` | `--qy-control-xl` | 44px | 40px |

外高角色示例为 `min-h-[calc(var(--qy-control-md)+var(--qy-control-mobile-extra))] sm:min-h-(--qy-control-md)`。名义尺寸可用 min-height 保持下限，长标签与放大文字可以增长；确需固定 height 的部件必须证明内容不会裁切，并提供合宜的换行或布局处理。无边框宿主内部可用高度就是其内容空间；有 1px 上下边框且无垂直 padding 的外框，内部高度为外高减 2px。

独立小控件采用 `relative touch-target` 时，宿主不得裁切 `::after`，不得让其他伪元素占用同一命中区。连续列表用行的最小命中尺寸，输入在粗指针下让真实输入区域至少达到目标，而非在外面盖一个无法编辑的透明层。检查宽屏粗指针、窄屏细指针、密集相邻控件与祖先 overflow，不能只验证 390px。

关系间隔用 `gap-(--qy-space-N)` 或已有关系角色；外部尺寸、内部空间与命中目标分别控制。**固定组件几何不得依赖“调大全局 spacing 后顺便变大”。** 修改全局 spacing 后，评审分别测间距和外框：间距可按关系改变，控件外高与命中目标不应被偶然连带改变。

需要独立调整的几何才新增角色：例如轨道厚度或特定图形直径不能被控件外高准确表达，且有明确消费部位。新增前列出职责、作用范围、集中修改入口与 computed 验证；仅把散落数值改名为 token 不通过。普通动作控件复用 `--qy-control-*`，不得因换组件名新增相同尺寸角色。

字体同样按职责选择。**内容档**表达层级：正文 `text-body`、辅助文字 `text-caption`、标题 `text-title`、数字核心 `text-metric`。**控件档**表达控件身份，按尺寸档选取：`text-control-xs-mobile sm:text-control-xs`、`text-control-sm-mobile sm:text-control-sm`、`text-control-md-mobile sm:text-control-md`、`text-control-lg-mobile sm:text-control-lg`（模式为「窄屏档 + `sm:` 桌面档」）。控件档当前分别落实 12/13/14/16px 的桌面与 14/14/15/17px 的窄屏预设；输入是否触发 iOS 缩放看实际字号，增高不能替代字号验证。

**控件档与内容档是两套名字，即使同值。** 基础层 §8 末尾说明：控件字号只随控件档变动，若写成内容档的别名，改 `body` 会连带改所有控件字号。清单的单一源是 `src/text-steps.ts`，新增文字档必须同时更新它，`cn()` 与预编译产物都从它取。

字号、行高、字重、字距由语义档位共同提供；数字、金额和时间用 `numeric`。中日韩 `lang` 下字距保持自然值，混排需检查实际语言标记与字体回退。布局方向用 `ms/me/ps/pe/start/end/text-start`；只在确有物理方向关系的箭头定位等情境说明例外。评审用长中文、英文、混排、放大文字和 RTL 检查结构，不以截断隐藏必要后果。

## 6. 变体原则

变体没有固定数量。最少数量由可证实的公共表达差异决定；每新增一个值都须增加一个不能由既有状态、尺寸、主题或组合承担的情境与验证。没有这样的情境就不增加，不能为了凑齐四级按钮而制造值。

给定一组动作，按以下顺序决定：

1. 列出对象、动作、范围、后果和真实可用条件。先区分执行、导航、选择、停止与退出；检查每项能否用名称解释，不先分颜色。
2. 写出当前任务重点。正常流程、异常保护、阅读与批量核对可以有不同重点；检查停止动作是否在异常中仍被机械弱化。
3. 将功能作用、视觉强调、风险、权限分列。危险后果由应用说明和保护，权限由应用执行；更强的填充不获得权限，较淡的外观不降低风险。
4. 先用组合、排列、表面关系和已有状态解决差异，再用集中主题解决产品身份。只在跨任务反复成立的公共表达差异上新增变体。
5. 对候选变体作来源与删去检验。合并两个变体后若识别、执行或保护无损，则合并；移除一个后没有实际情境缺口，则删除。
6. 分离轴：`variant` 表达公共呈现差异，`size` 表达几何档位，选择/展开/忙碌是状态，品牌/明暗/密度是独立主题轴。检查改 variant 后事件、权限与持久化没有变化。

主题入口固定归属：项目身份写 `html[data-brand]`，明暗由 ThemeProvider 写 `.light/.dark` 或显式属性模式的 `data-theme="light|dark"`，密度写 `data-density`。组件不把品牌写入 `data-theme`；compact 可以收紧关系间距，不能机械缩小文字、焦点或触摸目标。评审组合切换三轴，检查其标记和公共状态彼此不被覆盖。

例如同一基础动作可有实心入口与融入既有工作面的轻表面入口；这只是两个已说明用途的呈现，不等于“主要/次要”永久排名。若只有一种用途成立，只交付一种。危险状态可用危险语义色，但不得用 `destructive` 样式实现授权或请求确认；评审调用相同事件，行为须由同一个应用契约决定。

| 禁令 | 变体或组合的失败方式 | 评审检验 |
|---|---|---|
| NG1 | 用新增说明重复动作或标题 | 删掉该句后，误操作或寻找困难的概率不变，则删除 |
| NG2 | 将有主次的内容做成等权入口 | 去掉装饰后仍应能指出当前重点 |
| NG3 | 每个变体自定圆角、字重和间距体系 | 同产品相同控件在不同页仍使用同一角色体系 |
| NG4 | 为每个变体再套无身份卡片 | 去掉边框后关系不变，则去掉围合 |
| NG5 | 在标题上方增加无用途 kicker/eyebrow | 不承担识别、决策或恢复的该行删除 |
| NG6 | 让动画代替真实状态或决定完成 | 禁用动画后状态与任务结果仍成立 |
| NG7 | 用消失的提示单独承载关键后果 | 提示消失后仍可确认该后果并继续恢复 |
| NG8 | 在界面解释变体、设计或实现方式 | 文案主语回到对象、后果或恢复动作；实现说明放文档 |

## 7. 动效契约

动效帮助辨认实际变化，不制造事实。事件立即更新状态与可访问语义，动画只是表现；评审禁用动画后，输入、退出、成功判定与恢复仍应可用。

| 变化 | 动效决定 | 评审检查 |
|---|---|---|
| 指针按下与释放 | `qy-pressable` 提供短促反馈，消费 press/fast 时长；disabled 与加载策略不得产生虚假执行反馈 | 按下后立即取消，控件回到实际状态，无尺寸跳动 |
| hover、焦点、选中配色 | 可过渡颜色与透明度；焦点语义和位置即时有效 | 快速跨越项目、Tab 操作，没有延迟可操作状态 |
| 浮层打开/关闭 | 从真实触发位置展开，消费原语 transform-origin；透明度与缩放；退出快于进入 | 连续开关与滚动重定位后无残留；97%/98% 差异见第 10 节 |
| 需要空间连续性的展开 | 可动画必要 height，不动画普通 width/top/left；选择指示条是限定例外 | 内容关系可跟踪，不能用 `transition-all` 连带移动布局 |
| 原位反馈、确有变化的内容进入 | 可用 `data-motion="fade-in"` 或 `rise-in`；stagger 只在顺序有助于识别时采用，不能延迟入口 | 状态即刻可读；长列表不逐项阻塞，取消进入仍可操作 |
| 键盘导航、程序要求即时变化 | 键盘由全局输入策略即时处理；需要即时变化的部件用已有 `data-instant` | 检查根 `data-ui-input="keyboard"` 下实际时长；不是组件另写一套键盘策略 |
| 减少动态效果 | 服从全局 `motion.css`，保留任务、名称和状态；不在组件重复实现用户偏好策略 | 模拟 reduce 后检查实际 transition 与 keyframes，不能只看是否写了 media query |
| 业务完成、权限撤回、错误判定 | 不等动画完成；不能靠脉冲、摇动或位移单独说明结果 | 取消动画和中途卸载均不会改变业务事实 |

时长使用角色：按压 `--qy-duration-press`（100ms）、快速反馈 `--qy-duration-fast`（140ms）、原位进入 `--qy-duration-feedback`（180ms）、展开 `--qy-duration-base`（220ms）；按角色取值，不因两个 token 当前接近就混用。缓动默认 `--qy-ease-out`，不新增回弹；规范仅允许 Toast 成功脉冲例外。抽屉曲线为 `--ease-drawer`，450ms 的命名时长入口未在当前 token 层确定，见第 10 节，不在组件散写数值补缺口。

中断规则：新的真实状态优先于未完成表现；打开中可关闭、退出中可重新打开、处理中可按应用能力退出或请求取消。清理组件拥有的计时器、监听与表现资源；不得用 `animationend`、`transitionend` 或定时器作为业务完成依据。评审在进入、退出与反馈中途反向操作，检查焦点、内容和退出入口，没有锁住输入的遮罩或陈旧回调。

## 8. 文案归属

| 内容 | 归属与入口 | 评审检查 |
|---|---|---|
| 与基础交互固定对应的内置文字 | 组件通过 `useUILocale().messages` 取得，例如展开、收起、关闭、清除与通用加载名称 | 切换语言后默认文字、可访问名称、隐藏文本一起改变 |
| 参数化的公共表达 | locale 中的函数接收对象或数量，避免组件拼接半句；已有格式化能力按实际 API 使用 | 中英句序、复数与长对象名可用，不硬编码一套标点 |
| 对象名、动作后果、字段名称、业务校验、权限与恢复策略 | 应用提供 children、Label、description、error 或显式文案 props | 组件不知道业务对象时不自动宣称“已保存”“可重试” |
| 调用方覆盖内置文案 | 对应 `aria-label`、`clearLabel` 等显式参数优先；没有覆盖才取 locale | 覆盖真正到达最终节点，不能被默认值重新盖住 |

新增内置文案前先证明它属于公共基础职责，再同时修改 `packages/ui/src/locale.tsx` 的 `UILocaleMessages` 与 `zhCN`，以及 `packages/ui/src/locales/en-US.ts` 的键。不得在组件另建字符串字典，也不得把应用后果偷放进通用 locale。评审检查两种语言同键、函数参数一致及覆盖路径；没有真实对象的图标按钮须由应用给出具体 `aria-label`。

文案只说明识别、决策或恢复所需的事实。Placeholder 不单独承担字段名称；状态不得只有颜色，装饰图标 `aria-hidden="true"`。评审删除重复解释后，必要名称与后果仍完整，不把设计自述放进产品界面。

评审者将对冻结基线运行独立相似性检查。该检查在实现者之外进行，不能要求实现者恢复基线或把旧源码交给实现者。共同原语接口、必要语义与公共 token 造成的相似须与成段结构、控制流和类串分别判断；低相似度不自动证明独立，高相似片段须逐项说明来源。冻结基线的保管位置、工具与阈值当前为 `UNVERIFIED`，不得伪报已运行或已通过。

## 10. 交付检查

按项记录对象、版本或提交、状态、证据和结论。`PASS` 是实际检查满足要求，`FAIL` 是观察到违例，`UNVERIFIED` 是证据不足以判定，`NOT_RUN` 是没有执行。**后两者绝不能报为通过。** 确实不适用记 `N/A` 并解释语义理由；存在硬要求的未核实项时，不能宣布该组件验收完成。

- [ ] 任务答案齐全：名称、对象、范围、后果、相关方法、部件与状态 owner 有事实对应；用一次删去检验与一次情境变化检验复查。
- [ ] 来源记录成立：原创文件头与实际过程一致；没有旧源码、前一上游归因或恢复操作；独立评审的冻结基线相似性检查有结果与人工判读。
- [ ] 解剖与 API 成立：每个部件可说明职责、slot 稳定；原生属性、事件、style、ref 和 render 实际到达宿主；受控拒绝变更、非受控初值与通知均按契约工作。
- [ ] 公共契约完整：基于 Base UI 的组件导出原语命名空间；已有 shadcn 迁移名称保留 alias，alias 不增加另一个实现；不为新组件凭空创造迁移历史。
- [ ] 表面、边界与几何来自角色：没有硬编码灰色或借 spacing 控制固定外高；记录外框、内部可用区和粗指针命中区；长文字和放大文字没有裁切必要内容。
- [ ] token 真正消费：新增或修改 token 时说明职责、范围和入口，重生成 `node scripts/gen-capabilities.mjs`、`node scripts/token-ledger.mjs`，再测实际 computed 值；源码引用数与旧观测不能代替实测。
- [ ] 状态可达且真实：覆盖本类别的必需状态和已启用的条件状态、相关组合；正常与相关失败、未知、取消或恢复路径可操作；刷新与布局变化保留仍有效的工作。
- [ ] 交互与可访问行为成立：按适用 APG 检查键盘全流程、名称、关联、可见焦点和返回；仅图标入口有具体名称，颜色不是唯一状态信息。辅助技术检查单独记录，截图不替代其证据。
- [ ] 明暗与尺寸实测：浅色/深色 × 桌面/390px 四组截图目检，并记录实际状态；按影响增加触摸、长文本、RTL、放大文字与混排检查，不把视口模拟称为真机通过。

## 11. 组件编写的文件骨架

下例为虚构的简单动作控件 `ActionControl`，文件名 `action-control.tsx`。它只有根部件 `data-slot="action-control"`，没有需要单独命名的内部部件；应用提供动作文字或图标的具体可访问名称。实心入口与融入工作面的轻入口是两个可解释的表面变体，不承担权限、校验或固定等级。它复用控件外高与触摸角色，无需新建专有尺寸 token。

原语已经实现 `useRender` 与事件合并，因此包装层直接透传 `render`，不套第二套宿主逻辑。`ButtonPrimitive` 是原语模块命名空间。示例最后的 `Button` alias 演示承担既有 Button/shadcn 迁移入口时的导出；只有分配到该入口的实现才保留它，其他新组件不得照抄该别名，也不得同时导出两个相冲突的 Button。

```tsx
// 本文件为 @qingye/ui 原创实现，依据 design.md、G0 与 Base UI 公共 API 编写。
"use client";

import * as ButtonPrimitive from "@base-ui/react/button";
import { cva } from "class-variance-authority";
import type * as React from "react";
import { cn } from "../utils";

// 唯一部件是动作根；变体只决定表面，不决定事件或权限。
const actionControlVariants = cva(
  [
    "relative inline-flex box-border items-center justify-center",
    "gap-(--qy-space-2) rounded-control border outline-none",
    "min-h-[calc(var(--qy-control-md)+var(--qy-control-mobile-extra))] sm:min-h-(--qy-control-md)",
    "px-(--qy-control-md-padding-bordered)",
    "text-control-md-mobile text-start sm:text-control-md",
    "touch-target qy-pressable",
    "focus-visible:ring-[length:var(--qy-focus-button-width)] focus-visible:ring-ring",
    "focus-visible:ring-offset-[length:var(--qy-focus-button-offset)] focus-visible:ring-offset-background",
    "data-disabled:pointer-events-none data-disabled:opacity-64",
  ].join(" "),
  {
    variants: {
      variant: {
        filled:
          "border-transparent bg-primary text-primary-foreground [&:not([data-disabled])]:hover:bg-primary/90",
        quiet:
          "border-transparent bg-transparent text-foreground [&:not([data-disabled])]:hover:bg-accent",
      },
    },
    defaultVariants: { variant: "filled" },
  },
);

export type ActionControlProps = React.ComponentProps<
  typeof ButtonPrimitive.Button
> & {
  variant?: "filled" | "quiet";
};

export function ActionControl({
  variant = "filled",
  className,
  render,
  ...props
}: ActionControlProps): React.ReactElement {
  return (
    <ButtonPrimitive.Button
      data-slot="action-control"
      type="button"
      {...props}
      {...(render === undefined ? {} : { render })}
      className={(state) =>
        cn(
          actionControlVariants({ variant }),
          typeof className === "function" ? className(state) : className,
        )
      }
    />
  );
}

export { ButtonPrimitive, ActionControl as Button };
```

React 19 的 `ref` 通过原语 props 透传，不为无用中间层增加 `forwardRef`。props 从原语实际组件的 `React.ComponentProps` 取得，保留其真实 ref 与 render 类型，不假定命名空间的 `Props` 别名与可调用组件完全相同。`variant` 省略时才取默认值，未把 `undefined` 强塞给只接受具体值的可选属性；`render` 条件展开同时保留元素与回调两种 API。调用方的 `className` 保留原语回调类型，并在实际状态下最后合并；`id`、事件、`aria-*`、`data-*`、style 与 ref 留在 `props` 中到达原语。替换为非 button 宿主时须按原语 API 提供 `nativeButton={false}` 并核对替换后的语义；hover 用真实 `data-disabled`，不依赖宿主一定是原生 button。

骨架的尺寸是下限，放大文字可增长；纵向 padding 为结构性 `0`，名义外高不依赖全局 spacing，水平 padding 扣除 1px 边框以保持文字起点。`touch-target` 的伪元素有 relative 宿主且未被本组件裁切，父布局仍须检查相邻目标和 overflow。它没有自持异步事实，因此不内置 loading、invalid 或成功判断；应用传入 `aria-busy` 时不得宣称本骨架已具备完整异步任务表达。纯动作无 selected/open，这两项为 `N/A`；接入切换或浮层能力时须换用相应原语并补齐第 4 节的状态契约。
