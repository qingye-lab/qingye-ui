# Qingye UI 5.5.0

5.5.0 changes when `Toc` renders, names the buttons attached to a field by action plus that field, keeps the names of Combobox and Autocomplete inputs while their popup is open, and completes the selection guidance (when to use, what to use instead) of twelve components. No public API is removed, but accessible names change; see Upgrading.

## Behaviour changes

- `Toc` renders nothing unless it has at least two items. One item gives the reader nowhere to go, so it is not a table of contents. Items are counted, not `h2` sections: one `h2` with two `h3` is three items and renders as before. Callers can drop their own single-section check. Whether the layout reserves a column for the table stays with the caller, by `items.length`.

- Buttons attached to a field are named by their action followed by the field's label, so two fields of one kind in one place no longer show two identical buttons: `NumberField` steps, `Combobox` and `Autocomplete` trigger and clear, `PasswordInput` reveal, `TagInput` add and remove, and the open and clear buttons of `DatePicker`, `DateTimePicker`, `DateRangePicker` and `DateTimeRangePicker`. Example: "增加 数量", "显示密码 当前密码". The label comes from `Field`, else the field's own `aria-labelledby`, its `<label>`, or its `aria-label`; range pickers use `Field`, the start input's caller-given `aria-labelledby`, or its `<label>`. Label text that is copied into the name follows later text changes. A field with no label keeps the action alone, and an explicit `aria-label` or `aria-labelledby` on the button still wins.
- `CodeBlock`: the copy button is named "复制代码" plus the block's title, language and first line, matching the code region.
- `SidebarToggle` without children takes the name of the navigation it controls (its `aria-labelledby` or `aria-label`), falling back to "侧边栏".
- `DataTablePattern`: the built-in pagination is named "分页" plus the table's caption, `aria-labelledby` or `aria-label`, so two paginated tables on one page have distinguishable navigation landmarks. An explicit `pagination["aria-label"]` wins, including `""`.
- `Transfer`: the select-all checkbox, the filter and each item checkbox are named through `aria-labelledby`, so they keep distinct names inside a `Field`.
- zh-CN: the single date-time picker says 日期时间 like the range picker (清除日期时间, 选择日期时间, 开始日期时间, 结束日期时间).

## Fixed

- `Combobox` and `Autocomplete`: an input named by a `<label for>` outside `Field` keeps its accessible name while the popup is open. Base UI hides the content outside the popup from screen readers, and browsers then dropped the name; such labels are now also referenced through `aria-labelledby`. An explicit `aria-label` or `aria-labelledby` and `Field` naming still win. When a wrapping label is present as well, nothing is added and native naming stays, so the wrapping label's text is not lost; that name still disappears while the popup is open, as documented on Combobox, Autocomplete and Label.

## Documentation

- Selection guidance for Autocomplete, Combobox, Command, ConfirmAction, the date and time pickers and fields, FileTrigger and FileUpload.
- `Meter` and `SeverityMark` no longer give opposite answers for one scene: a reading with a unit over a valid range is Meter, an ordered level read as its name is SeverityMark.
- `Button`: a disabled reason must be visible page text, not only a Tooltip or `title`, because tooltips do not open on touch screens. A new demo uses `aria-disabled` with `aria-describedby`. `Tooltip` states the same rule.

## Upgrading

- Code or tests that expect `Toc` to render a single item need updating.
- Tests or scripts that find the attached buttons listed above, the `CodeBlock` copy button, a bare `SidebarToggle` or `DataTablePattern` pagination by exact name must use the new names, or match the action at the start of the name.
- zh-CN strings containing 日期和时间 now read 日期时间.
- 5.4.1 was never released; its changes are part of 5.5.0.
