# Qingye UI 5.5.0

5.5.0 changes when `Toc` renders, keeps the names of Combobox and Autocomplete inputs while their popup is open, and completes the selection guidance (when to use, what to use instead) of twelve components. No public API is removed.

## Behaviour changes

- `Toc` renders nothing unless it has at least two items. One item gives the reader nowhere to go, so it is not a table of contents. Items are counted, not `h2` sections: one `h2` with two `h3` is three items and renders as before. Callers can drop their own single-section check. Whether the layout reserves a column for the table stays with the caller, by `items.length`.

## Fixed

- `Combobox` and `Autocomplete`: an input named by a `<label for>` outside `Field` keeps its accessible name while the popup is open. Base UI hides the content outside the popup from screen readers, and browsers then dropped the name; such labels are now also referenced through `aria-labelledby`. An explicit `aria-label` or `aria-labelledby` and `Field` naming still win. When a wrapping label is present as well, nothing is added and native naming stays, so the wrapping label's text is not lost; that name still disappears while the popup is open, as documented on Combobox, Autocomplete and Label.

## Documentation

- Selection guidance for Autocomplete, Combobox, Command, ConfirmAction, the date and time pickers and fields, FileTrigger and FileUpload.
- `Meter` and `SeverityMark` no longer give opposite answers for one scene: a reading with a unit over a valid range is Meter, an ordered level read as its name is SeverityMark.
- `Button`: a disabled reason must be visible page text, not only a Tooltip or `title`, because tooltips do not open on touch screens. A new demo uses `aria-disabled` with `aria-describedby`. `Tooltip` states the same rule.

## Upgrading

- Code or tests that expect `Toc` to render a single item need updating.
- 5.4.1 was never released; its changes are part of 5.5.0.
