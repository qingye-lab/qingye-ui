# Qingye UI 1.0.0 — unreleased candidate

**Status: local, unreleased candidate.** `packages/ui/package.json` is set to 1.0.0; this document does not announce a published release or successful execution of the Release workflow. The latest-release download command selects the latest published GitHub Release, not this workspace version.

The current source contains 87 component modules rewritten under the root [design.md](../../design.md). This is a major API and visual migration, not a drop-in update from 0.4.x. Applications continue to own data, business rules, requests and persisted state.

## Breaking API changes

| Area | Current contract and migration |
| --- | --- |
| Button | `variant` is `solid`, `bordered` or `quiet`; `tone` is `neutral` or `danger`; sizes are `xs` through `xl`, with `shape="icon"` for icon controls. Replace former variant/size names and loading assumptions. Supply actual `state`: `idle`, `waiting`, `in-progress`, `unknown` or `failed`. Busy and unknown states block activation while retaining the action's identity. A danger action requires a visible consequence through `ButtonProtection` or a nonempty DOM description linked by `aria-describedby`; this does not grant authorization or automatically confirm an action. |
| Field | Application state supplies `invalid` and error content. Automatic validation props (`validate`, `validationMode`, `validationDebounceTime`, `actionsRef`) are not part of Field's public API. Native form constraints remain available. Use `FieldLabel` with a registered control for a field label; `FieldTitle` alone is not a label association. `FieldSet` / `FieldLegend` aliases are removed; use the separate `Fieldset` / `FieldsetLegend` component entry. |
| Media queries | `useIsMobile` is removed. `useMediaQuery("max-md")` queries the former width condition (below 768px); select the query that matches the layout decision. A width match does not identify a physical device. |
| Component parts | Former naming aliases such as `DropdownMenu*`, `DialogContent`, `SheetContent` and `TabsTrigger` are not exported. `TooltipContent` remains an exported alias of `TooltipPopup`. Use the current component declarations and installed catalog rather than assumed alias mappings. |
| Tabs | Use `Tabs`, `TabsList`, `TabsTab` and `TabsPanel`. Activation is manual by default: arrow keys move focus; Enter/Space selects the focused tab. `TabsList` can explicitly opt into `activateOnFocus`. `TabsPanel` defaults to `keepMounted=true` to preserve local panel state; choosing `false` permits unmounting and draft loss. |
| Tree | Supply `nodes` with globally unique stable IDs and nonempty labels. Expansion and selection are separate facts (`expandedIds`, `selectedId`); keyboard focus movement does not select a node. Change callbacks receive cancellable details. Disabled nodes are skipped; when the tree owns focus and no enabled item remains, focus returns to the tree container. |
| Table / DataTable | Table is a native `table`; put horizontal scrolling on the separate `TableContainer`. Use caption and header cells for real relationships, `scope="row"` for row headers, and `data-density` for density. Comparison columns are retained. Sorting and result facts come from the application or explicitly configured DataTable state; DataTable does not fetch data or fabricate totals. |
| Chart | Replace the former wrapper/tooltip/legend API with `Chart` and its explicit label, named axes, series and rows. Values are finite numbers (including zero) or named `unknown` / `not-applicable` values. The default plot, legend and visible equivalent table share the same data. Non-data states are explicit; unknown values are not zero or interpolated observations. Custom plots receive the same projection. |
| Modal lifetime | `DialogPopup`, `AlertDialogPopup` and `DrawerPopup` own their Portal and enforce `keepMounted=false`. `portalProps` excludes this option; even a runtime override cannot retain a closed modal Portal. Keep drafts in application state if they must survive closing. This supported contract preserves sibling modal accessibility isolation with the installed Base UI primitive. It differs from the retained-panel default in Tabs. |

### Removed component entries

These nine entries are removed without compatibility exports:

| Removed | Migration boundary |
| --- | --- |
| `sheet` | Use `drawer` for the corresponding side-panel relationship. |
| `disclosure` | Use `collapsible`. |
| `frame` | Use Card only for an independent content boundary; compose layout and semantic structure explicitly. |
| `preview-card` | Compose the application's actual preview content from public components. |
| `spinner` | Express pending state on its real object using Button state, StatusDot and/or `aria-busy`. |
| `skeleton` | Preserve still-valid content during refresh and present its actual pending state. |
| `command` | Compose a command or search surface from current public controls and a suitable container. |
| `menubar` | Use NavigationMenu for navigation or Menu for commands according to the task. |
| `resizable` | Own any required pane-resizing behavior in the consuming project's layout. |

`search-input` and `password-input` are also no longer standalone entries. Use Input attributes and public InputGroup combinations for those input forms. The [layering decision](../decisions/component-layering.md) records the component inventory and boundary decisions.

## Breaking visual changes

- All 87 component modules use the rewritten defaults. Existing screenshots and selectors targeting old part structure require review against the current API and actual application composition.
- **Card has no default shadow, padding or internal header/footer layout.** It supplies an independent content boundary; the caller composes its contents and spacing.
- Button emphasis, danger treatment and control sizes follow the new variant/tone/shape contract. Keyboard focus is expressed inside the owning control or surface rather than by the former outer treatment.
- Table keeps a native comparison surface with an explicit scrolling container. Chart includes named axes, differentiated series and a visible equivalent table, changing its layout and capacity requirements.

The design guide is the source for these relationships and documented presets. This note does not introduce another set of styling rules. Check both light and dark themes in the consuming application's real states before adopting the candidate.

## Documentation and distribution changes

The site now presents 83 components and six simple compositions: InputGroup, Tabs, FilterBar, BulkActionBar, DataTable and Toolbar. The former dashboard, mail, media Studio and business task example routes have been removed. The separate private Theme Studio remains available in the workspace.

Chinese and English guides and AI resources are generated from the authored sources, including `design.md`, `design.en.md`, `ai/SKILL.md`, `ai/SKILL.en.md` and versioned `ai/v1.0.0/` component resources with an `en/` index. The six method names remain 名实相符、相成相制、布白有用、随境取度、展开有据、进退相承. Consumer adoption references belong in that project's existing `AGENTS.md` and `design.md` using the guide's snippets.

`@qingye_lab/ui` is the 1.0.0 candidate. `@qingye/tooling` is 0.5.0 for the renamed UI/config contract; `@qingye/studio` remains private at 0.4.0. Versions follow each package's actual API changes. The [Release workflow](../../.github/workflows/release.yml) matches the tag to the UI version and packs UI/tooling at their own manifest versions; a UI major bump does not require matching tooling or private Studio versions.

Implementation and verification status are recorded in the [rewrite roadmap](../plans/2026-10-03-rewrite-roadmap.md) and its linked execution reports. Local checks, generated resources and this candidate note do not establish release publication or acceptance of an external consumer migration.
