# Qingye UI 4.2.0

4.2.0 adds explicit capabilities for long collections, table comparison, point inspection and styled scrolling. It repairs the containing block of Dialog and AlertDialog popups after entry motion. Existing static and native defaults remain available.

## Added

- `VirtualList`: `measurement="dynamic"` observes actual row height. `itemSize` becomes the estimate; stable `getKey` identities retain reading position after history insertion and above-viewport resizing. `actionsRef` exposes `scrollToIndex(index, {align})` and `scrollToEnd()`, separately from the native viewport ref. `followEnd` follows appended records only when the reader was at the end. Commands do not move focus; keyboard navigation does.
- `DataTable` and `DataTablePattern`: column `size/minSize/maxSize` now reach native fixed table layout when explicitly configured; otherwise automatic layout remains. `ellipsis` preserves full noninteractive text in the DOM/title. `selectionAppearance="checkbox"` removes selected-row paint while retaining real checkboxes and independent active-row paint. Advanced `onRowActivate(row)` and Pattern `activeRow={{trigger:"row"}}` exclude nested editing and actions. `virtualization={{height,estimateRowHeight,overscan}}` measures native rows and retains offscreen focus; sorting, paging and selection still refer to the table's current model.
- `Sparkline`: opt-in `tooltip` and `getPointLabel(index)` provide pointer, keyboard and tap point inspection. Null remains unknown; zero remains a real value. Escape and blur dismiss the public Tooltip, which can escape clipping containers. The default static image and summary remain.
- Menu items: `inset` reserves a logical icon column; checkbox/radio `markerPosition="start"` supports leading marks. Existing size roles determine the responsive icon space. The default marker remains at the end.
- ScrollArea advanced parts: `ScrollAreaRoot`, `ScrollAreaViewport`, `ScrollAreaContent`, `ScrollAreaScrollbar`, `ScrollAreaThumb`, `ScrollAreaCorner` and `ScrollAreaPrimitive`. Native refs/events belong on Viewport. Both axes have real measurable and draggable thumbs; kept no-overflow tracks are invisible and noninteractive. The existing `ScrollArea` remains the native scrolling element.

## Fixed and clarified

`DialogPopup` and `AlertDialogPopup` establish `position:relative`, anchoring absolute descendants to the popup after animation transforms finish. Field docs distinguish contextual FieldLabel/FieldDescription from standalone Label. Pagination docs state the accessible-name requirement when replacing default direction text with icons.

## Compatibility and visual changes

The new collection, tooltip, menu-marker and styled-scrollbar behavior is opt-in. Explicit column sizing now produces the dimensions specified by the consumer; long tables retain horizontal scrolling. Menu `md` padding follows the existing fill-padding role, including compact density. Custom complete locale objects must provide the four new Sparkline message keys or extend a built-in locale. Rebuild Tailwind output or use the refreshed compiled `ui.css`.

Measured windows depend on stable unique keys and a usable viewport. Unmounted row heights remain estimates until measured. Applications own remote loading, request races, drafts, activation effects and the meaning of follow-end. Table virtualization applies to the current page/model, not every server result.

The runtime adds exact `@tanstack/react-virtual@3.14.22` and its MIT-licensed core dependency; the library owns semantics, focus and design. TanStack Table remains an optional peer for DataTable. Current Chinese/English AI resources are under `ai/v4.2.0/`; older version directories remain in Git and are excluded from this tarball.

## Verification and distribution

The release gates include targeted interactions, complete workspace tests, type/API/fact checks, builds, serial built-preview browser audits and isolated tarball installations with Tailwind and precompiled CSS. The new public-demo regression is `node scripts/run-browser-audit.mjs --consumer-migration`; its report records the actual browser lifecycle and failures.

See [the completion record](../plans/2026-10-23-consumer-migration-completion.md) for observed gate results and remote publication status. A versioned build or tarball does not establish npm publication. External consumer acceptance requires its actual migration commit and reachable pages; automated library evidence does not establish physical-device touch or screen-reader speech.
